# 車輛拍賣平台 —— 純前端 Demo

零後端、假資料的可操作 Demo，用來展示抵押車輛線上拍賣平台的功能與拍賣機制。

## 快速開始

```bash
npm install
npm run dev
```

開站後在登入頁點任一帳號即可進入，不需密碼。

| 帳號 | 角色 | 用途 |
|---|---|---|
| 拍賣營運（田中 健一） | 公司人員 | 車庫與拍賣管理，**唯一看得到底價**的角色 |
| 車輛登錄員（小林 美咲） | 公司人員 | 只能進車庫管理，**看不到底價**、沒有拍賣管理選單 |
| 系統管理員（中村 誠） | 公司人員 | 同樣看不到底價，也不做拍賣設定 |
| 山田商事 | 二手車商 | 主要示範視角，預設情境都以他為主 |
| 鈴木自動車 | 二手車商 | 用來演示競價與被超越 |

三個內部角色對應 Phase 1 §1.1。**切到「車輛登錄員」就能直接演示底價權限隔離**——
側邊欄少一項、拍賣頁進不去、卡片上沒有底價提示。

## Demo 控制台

右下角的浮動控制台可以手動觸發任何狀態改變，不必等真實時間流逝。

- **快捷鍵**　`` ` `` 開合、`Esc` 收成精簡
- **三段收合**　圓鈕 → 窄橫條 → 完整面板；可切到四個角落，位置與模式都會記住
- **不影響瀏覽**　全程 `position: fixed` overlay，頁面 layout 寬度不會因開合而改變；點面板外也不會關閉，方便邊操作邊看頁面反應

功能區塊：

| 區塊 | 能做什麼 |
|---|---|
| 時間 | 快轉 1 分／10 分／1 小時／1 天；加速 1x／10x／60x／暫停；回到真實時間 |
| 模擬出價 | 以任一車商身分出價（含 4 家不可登入的），可連續隨機出價 |
| 強制狀態 | 立即開標／立即結標／強制流標／強制議價 |
| 推送通知 | 11 種通知類型任選，指定收件者立即送出 |
| 場景 | 一鍵切換角色、載入 7 組預設情境、重置為初始資料 |

**示範時建議直接用「場景」區的預設情境**，一鍵就是要展示的畫面：

- 即將結標的熱門車（剩 2 分鐘、8 次出價、你領先）
- 你被超越了（通知已在鈴鐺裡）
- 軟結標延長中（已延長 9 分鐘）
- 議價中（收到議價邀請）
- 密封投標開標前（3 家已投標、金額全部隱藏）
- 流標待處理（差底價超過 10%，營運要決定後續路徑）
- 上架前檢核沒過（照片不足、文件未到齊、底價未核准）

## 拍賣機制

Phase 1 只做兩種方式（§5）：

| | 定時開標 | 密封投標 |
|---|---|---|
| 看得到目前最高價 | ✅ | ❌ 只看得到自己的 |
| 建議長度 | 3–7 天 | 2–3 天 |
| 軟結標 | 前 3 分鐘 → 延 3 分鐘（上限 60 分） | 無 |
| 出價次數 | 不限 | 只能投一次 |
| 立即成交價 | ❌ | ✅ |

**出價一律為手動出價**。Phase 1 不做代理／自動出價（§0、§4.1），也不做撤標（§6.3）——
車輛可否處分必須在上架前確認。

**出價級距**（日圓）：< 50 萬 → 5,000／50–200 萬 → 10,000／200 萬以上 → 50,000。每筆拍賣也可改為固定金額。

**結標判定**：最高價 ≥ 底價 → 成交；差距 < 10% → 議價中（24 小時，逾期依序問下一位）；否則流標。

**流標後續處理**（§4.4）在監控頁提供五條路徑：換方式重掛（標為優先）、調整底價重掛、
整備後重新上架、轉固定價格長期掛售、整批出清。降價重掛設有 2 次上限，避免車商養成等降價的習慣。

**上架前檢核清單**（§2.2）四項全過才能建立拍賣：照片 ≥ 20 張、必填欄位齊全、文件到齊、底價已核准。

## 機密資料的隔離

底價與貸款餘額兩項永不出現在車商可見的畫面（§1.3）。`src/architecture.test.ts` 在原始碼層面把這件事鎖住：
車商頁面不得引用 `reservePrice` / `loanBalance` / `ReserveHint`，並且守住「代理出價與撤標不得回到程式碼裡」。

底價在公司內部也不是人人可見——只有 `canSeeReserve` 的角色看得到，包含「即將結標未達底價」那則內部通知。

## 資料

全部為假資料，狀態存在 localStorage。控制台的「重置為初始資料」可回到乾淨狀態。

初始資料：27 台車輛（12 台純在庫）、15 筆拍賣涵蓋兩種方式與五種狀態、8 個帳號、8 則歷史通知。
`faker.seed(20260728)` 固定，重置後內容完全相同。每 5 台車刻意留一台照片與文件不齊，用來示範上架前檢核。

車輛照片來自 loremflickr；**無網路時自動改用本地產生的 SVG，不會出現破圖**。

## 架構

一個虛擬時鐘驅動一組純函式引擎，引擎回傳新資料與事件陣列，事件再轉成通知寫入 store。所有頁面只讀 store，不含任何狀態轉換邏輯。

```
虛擬時鐘 → 每 250ms tick → advanceAuctions(data, now) → { data, events }
                                                           ↓
                                             events → 通知 → toast / 鈴鐺
```

```
src/
  engine/    拍賣規則（純函式，不讀時間也不讀 store）
  clock/     虛擬時鐘（加速、暫停、快轉）
  store/     zustand + localStorage
  data/      假資料、車款清單、預設情境
  components/
  pages/
```

兩個刻意的設計決定：

- **倒數計時不寫回 store**：`<Countdown>` 用自己的 1 秒 interval，每秒重繪只影響那個元件，不會觸發 store 寫入。
- **`advanceAuctions` 沒有變化時回傳原本的物件參照**，所以 250ms 的迴圈在拍賣沒事發生時完全不造成重繪或 localStorage 寫入。

## 測試

418 個測試，分三層：

- **引擎**（TDD）：級距邊界、軟結標、結標三分支、議價輪替、冪等性
- **頁面**：以 Testing Library 掛起整個路由樹，驗證每個畫面的行為與底價隔離
- **架構守衛**：在原始碼層面鎖住機密資料隔離、引擎純度、控制台的 overlay 約束
- **console 乾淨度**：七個主要頁面渲染時不得出現 Base UI 或 React 的警告

## 已知限制

### Base UI 與 Radix 的差異（重要）

shadcn 目前的預設 style（base-nova）底層是 **Base UI 而不是 Radix**。網路上多數 shadcn 範例是 Radix 寫法，照抄會出問題。目前踩到三個：

| 情況 | Radix 寫法 | 這裡要怎麼寫 |
|---|---|---|
| Trigger 換成別的元件 | `asChild` | `render={<Button/>}` |
| 按鈕外觀的連結 | `<Button asChild><Link/></Button>` | 用 `<ButtonLink>`（見下） |
| 下拉選單的標題 | `<DropdownMenuLabel>` 可獨立使用 | 必須包在 `<DropdownMenuGroup>` 裡，否則**執行時拋錯** |

**按鈕外觀的連結一律用 `<ButtonLink>`**，不要寫 `<Button render={<Link/>}>`。後者會讓 Base UI 警告 button 語意被破壞；而它建議的 `nativeButton={false}` 雖然消掉警告，卻把 `<a>` 的 role 蓋成 `"button"`，對導覽元素語意更糟（螢幕閱讀器會唸成按鈕，也失去連結的操作提示）。`ButtonLink` 只借用 `buttonVariants` 的樣式，保留原生 `<a role="link">`。

**教訓**：這類錯誤只在「元件被打開」時才出現。DropdownMenu 的 bug 之所以漏掉，就是因為當時沒有任何測試點開過它——其他 Dialog / Popover / Checkbox 都有測試點開，所以都沒壞。**新增任何 Base UI 複合元件時，測試一定要點開它。**
- 視覺只做到規格定的色票與密度規範，沒有再跑一輪專門的視覺打磨。
