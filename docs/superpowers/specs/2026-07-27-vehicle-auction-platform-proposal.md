**本階段暫不討論**

**業務前提**

車輛在放款時已過戶至公司名下，因此處分時公司即為登記車主，可直接銷售，不需經過司法拍賣程序。這代表拍賣規則（底價、天數、出價方式、結標方式、付款條件、違約條款）都可由公司自行設計。

## 3. 拍賣機制設計

### 3.1 三種拍賣型態

#### 選項 A：定時開標

車輛上架後掛 3–7 天，車商在期間內隨時出價，看得到目前最高價，時間到最高價得標。

| 優點 | 缺點 |
|---|---|
| 車商不必準時到場，參與門檻低 | 若參與者少，價格不易拉高 |
| 車輛可隨到隨上架，不必等湊場次 | 需要防止最後一秒出價的機制 |
| 有競價過程，價格會被互相推高 | 拍賣週期較長（3–7 天） |
| 車商有時間評估車況再出價 | 缺少現場競價的節奏感 |

**適合本業務的原因**：回收車輛是陸續進來的，不是成批到貨。定時開標不需要湊滿場次，查驗完成後即可上架。

#### 選項 B：即時同步拍

固定場次（例如每週三下午），車商同時上線，每台車 45–90 秒競價，無人加價即落槌。日本大型車拍（USS、TAA、JU）的標準形式。

| 優點 | 缺點 |
|---|---|
| 成交價通常最高，現場競價會推高價格 | 車商必須準時到場，缺席者無法參與 |
| 不存在最後一秒出價的問題 | 需要湊滿場次，車輛需等待 |
| 一場能處理大量車輛 | 車商決策時間短，可能傾向保守 |
| 貼近日本車商既有的操作習慣 | 系統建置與維運成本較高 |

#### 選項 C：密封投標

車商在期限內投一次密封報價，期間看不到其他人的出價，開標時最高價得標。

| 優點 | 缺點 |
|---|---|
| 車商間難以互相確認出價，可抑制聯合行為 | 成交價通常偏低，車商會較保守 |
| 不存在最後一秒出價與跟價行為 | 缺少競價熱度，車商參與感較低 |
| 車商不需盯盤，操作成本最低 | 資訊不透明，需要車商信任平台 |
| 適合沒有公開行情、難估值的車 | 若只有一人投標，價格可能偏低 |
| 不會對外揭露公司的處分價格 | —— |

**適合的情境**

- 稀有車、高價車、改裝車、事故車、大型商用車（沒有公開行情，公開競價時車商容易互相觀望）
- 一次上架多台同款車
- 不希望對外揭露處分價格的車輛
- 需要抑制買方聯合行為時

**密封標的計價方式**

| | 第一價格（付自己出的價）⭐ | 第二價格（付第二高價 + 一級距） |
|---|---|---|
| 車商行為 | 傾向略保守出價 | 理論上會出真實估值 |
| 實務考量 | 規則直觀，車商容易接受 | 賣方掌握所有出價資料，車商難以驗證第二高價的真實性 |

⭐ 建議採第一價格。第二價格在理論上更有效率，但需要車商對平台有很高的信任基礎。

### 3.2 建議的組合策略

⭐ 建議把「拍賣型態」做成車輛上架時的可選項目，由營運人員逐台判斷，而非全站統一。

| 車輛狀況 | 建議型態 | 理由 |
|---|---|---|
| 常見車款、有明確市場行情 | 定時開標 | 車商敢出價，競價效果好 |
| 稀有 / 高價 / 事故車 / 難估值 | 密封投標 | 避免車商互相觀望 |
| 一次多台同款車 | 密封投標 | 避免同款車互相排擠 |
| 定時開標流標過一次 | 密封投標，或調整底價重掛 | 換機制可能吸引到不同買家 |
| 已流標兩次 | 轉固定價格長期掛售 | 不再佔用拍賣資源 |
| 車商數量成長、生態成熟後 | 即時同步拍 | 屆時才有足夠人氣支撐場次 |

這個做法的代價是營運人員需要判斷力與訓練，規則也較多。但好處是每台車都能用相對合適的方式銷售，且流標車有明確的後續路徑。

### 3.3 代理出價（自動出價）

即討論中提到的「設定上限自動出價」。

**運作方式**

1. 車商輸入願意出的最高金額，例如 85 萬
2. 系統不會直接跳到 85 萬，只出「打敗目前最高價所需的最小金額」
   - 目前最高 70 萬、級距 1 萬 → 系統代出 71 萬
3. 他人出 75 萬 → 系統自動跳到 76 萬，一路到 85 萬為止
4. 超過 85 萬時停止，並通知車商已被超越

| 優點 | 缺點 |
|---|---|
| 車商設定一次即可，不必盯盤，明顯提升參與度 | 車商初期需要理解機制，需要說明 |
| 成交價會更接近車商的實際願付價格 | 部分車商偏好親自掌控每次出價 |
| 未來若導入即時同步拍，此機制可直接沿用 | —— |

⭐ **重要**：車商設定的出價上限屬機密資料。公司內部人員原則上不應查看進行中拍賣的代理出價上限；若營運上有必要，建議設定核准與紀錄機制。

### 3.4 出價級距

依價格分段設定最小加價幅度。

| 目前價格 | 最小加價（示意） |
|---|---|
| 50 萬以下 | 5,000 |
| 50 萬 – 200 萬 | 10,000 |
| 200 萬以上 | 50,000 |

級距的取捨：太小會讓競價過程冗長，太大會讓車商放棄加價。需依當地車價水準調整，不宜一套通用。

❓ **待確認**：車商習慣的加價幅度是多少？

### 3.5 即刻成交價（選配）

標示一個「立即成交價」，任何人出到該價立即結標。

| 優點 | 缺點 |
|---|---|
| 快速去化，縮短處分時間 | 相當於自行設定價格上限，熱門車可能因此少賣 |
| 給急需車源的車商明確出口 | 設定不當時，太高沒人用、太低則不划算 |
| —— | 部分車商可能只看此價格，不再參與競價 |

⭐ 建議列為選配，由核價主管逐台決定。較適合冷門車或希望盡快去化的車輛。

### 3.6 結標規則

在「時間到就結束」的拍賣中，理性策略是在最後一秒才出價，讓其他人來不及回應。這會使成交價低於實際競價潛力，也影響車商的參與意願。

| 選項 | 做法 | 取捨 |
|---|---|---|
| 硬結標 | 時間到即結束 | 規則單純、時間可預測，但直接鼓勵最後一秒出價 |
| **自動延長（軟結標）** ⭐ | 結標前 N 分鐘內有新出價 → 結標時間往後延 N 分鐘 | 最後一秒出價失去意義；缺點是結標時間不可預測 |
| 隨機結標時間 | 結標時間在一個區間內隨機決定 | 有效，但車商通常不喜歡不可預測的規則 |
| 改用密封投標 | 見 3.1 選項 C | 沒有此問題，但犧牲競價熱度 |

⭐ **建議採自動延長**

- 觸發條件：結標前 **3 分鐘**內有新出價
- 延長時間：往後延 **3 分鐘**
- 延長次數：不限，或設一個總上限（例如最多延長 60 分鐘）

實際效果是最後一秒出價後，其他人仍有 3 分鐘可以回應。這是 Yahoo 拍賣與多數車拍平台的通行做法。附帶效果是熱門車常會延長 10–20 分鐘，價格在延長期間仍有上升空間。

❓ **待確認**：3 分鐘為常見值，若車商習慣較快節奏可縮短，建議試營運後調整。

### 3.7 底價策略

底價的作用是為每台車設定一個成交價下限，是價格保障的主要機制。

| 選項 | 做法 | 優點 | 缺點 |
|---|---|---|---|
| 1. 無底價 | 低價起標，出多少賣多少 | 人氣最高，成交率接近 100% | 單台車的成交價不受保障 |
| 2. 公開底價 | 起標價即為底價 | 規則單純，車商清楚門檻 | 價格容易停在底價附近，較難往上競價 |
| 3. 隱藏底價 ⭐ | 低價起標，過程中只顯示「尚未達到底價」 | 兼顧人氣與價格保障，車商接受度高 | 流標率偏高；車商可能出了價卻始終達不到底價 |
| 4. 隱藏底價 + 流標後議價 ⭐⭐ | 同選項 3，未達底價時啟動議價流程 | 成交率明顯提升，保留公司最終判斷權 | 若車商掌握規則，可能傾向先出低價等議價 |

⭐ 建議採選項 4，詳見 3.8。

#### 底價的計算基礎 ❓

這是本提案最關鍵的待確認事項。有兩種基礎邏輯，結果可能相差很大：

| 邏輯 | 做法 | 取捨 |
|---|---|---|
| 保本邏輯 | 底價 = 貸款未償餘額 + 回收/保管/處分費用 | 帳面上不產生損失，但若車輛市價低於餘額（例如餘額 90 萬、市價 70 萬），底價將難以達成，車輛可能長期無法售出 |
| 市場邏輯 | 底價 = 市場估值 × 折扣 | 車輛可順利售出、處分時間短，但需認列帳面差額 |

⭐ **業界常見做法**：兩者取較低者，並依差額金額分層核准。

| 情境 | 核准層級 |
|---|---|
| 底價 ≥ 貸款餘額 + 費用 | 營運人員可自行設定 |
| 底價 < 貸款餘額 | 需主管核准 |
| 差額超過一定金額 | 需更高層核准 |

**一個建議在制度上納入的考量**：訂底價時，除了「售價與貸款餘額的差額」，也建議把「車輛繼續持有的成本」（保管費 + 折舊）納入比較。若只看前者，底價容易偏高而使車輛滯銷，最終的總結果可能不如較早售出。這需要先能估算出持有成本。

❓ **待確認**

- 目前一台回收車的售價是誰決定的？依據什麼？
- 有沒有可用的估值來源或工具？
- 認列差額需要什麼層級核准？金額門檻是多少？
- 車輛保管成本一天／一個月大約多少？
- 目前的平均回收率（成交價 ÷ 貸款餘額）大約是多少？

### 3.8 流標後的處理

車輛拍賣的流標率通常在 20–40%。若流標後只能重新上架，車輛需再等一輪，持有時間會明顯拉長。

#### 建議機制：流標後議價（日本車拍稱「商談」）

1. 結標時最高出價 78 萬、底價 82 萬 → 進入「議價中」狀態
2. 系統通知最高出價者：出價未達底價，是否願意加價至 82 萬成交，給 24 小時決定
3. 同時核價主管可在後台調整底價、直接接受 78 萬
4. 若最高出價者放棄，可依序詢問第二、第三高出價者
5. 全部失敗 → 正式流標，轉入重新上架或固定價格銷售

| 優點 | 缺點 |
|---|---|
| 成交率可明顯提升，縮短持有時間 | 若規則被車商掌握，可能傾向先出低價等議價 |
| 保留公司對每台車的最終判斷權 | 增加一個人工判斷環節 |
| 實作成本低，屬結標後的一段流程 | 議價期間車輛仍在庫 |

**建議的配套規則**

- 議價僅在「未達底價幅度小於一定比例」（例如 10%）時啟動
- 議價金額由系統直接開出（即底價），不開放來回議價
- 將「議價成交比例」納入車商行為統計

#### 流標車輛的後續路徑

| 路徑 | 適用時機 | 取捨 |
|---|---|---|
| 調整底價重新上架 | 底價明顯偏高 | 做法直接，但若成為慣例，車商會傾向等待下一輪的較低價格 |
| 改換拍賣型態重掛 ⭐ | 第一次流標 | 可能吸引到不同買家，需營運判斷 |
| 轉固定價格長期掛售 | 已流標兩次 | 不再佔用拍賣資源，但去化較慢 |
| 整備後重新上架 | 車況為主要問題 | 可能提升成交價，但需先投入成本 |
| 整批出清 | 長期無法去化 | 一次回收現金，價格較低 |

⭐ **建議**：優先考慮「換型態」而非「降價」，並對降價重掛的次數設限，以避免形成觀望效應。

### 3.9 撤標與借款人贖回

車輛在拍賣進行中，借款人可能清償欠款、談成展期或提出異議，此時需要能中止拍賣。

| 議題 | 選項 |
|---|---|
| 誰能撤標 | (a) 營運人員即可　(b) 需主管核准 ⭐ |
| 已有出價時如何處理 | (a) 直接取消並通知　(b) 取消並給予補償　(c) 有出價後不允許撤標 |
| 是否說明撤標原因 | (a) 僅顯示「已下架」⭐　(b) 說明原因（涉及借款人資料） |

⭐ **建議**：允許撤標但強制填寫理由並留存紀錄，同時將「撤標率」納入營運報表。

**需要注意的一點**：車商在出價前會投入時間評估車況，若撤標比例偏高，會影響車商的參與意願。因此理想的做法是在上架前就確認車輛可處分，把問題處理在上架之前，而非依賴撤標。建議設定一個撤標率的觀察門檻（例如 5%），超過時檢討上架前的作業流程。

❓ **待確認**：從車輛回收到可以處分，中間是否有等待期？借款人的贖回權有多久？實務上多常發生拍賣中清償的情況？

## 4. 公司人員功能

### 4.1 車輛登錄與上架

完整的前置流程大致是：

```
違約判定 → 車輛回收 → 入庫 → 查驗拍照 → 整備決策 → 定價 → 上架
```

**系統要涵蓋多長的流程？**

| 選項 | 範圍 | 取捨 |
|---|---|---|
| A. 只做「上架」 ⭐ | 車輛資料手動輸入，前段流程仍在線下 | 範圍單純、上線快，但無法掌握「入庫到上架」這段的耗時 |
| B. 涵蓋入庫到上架 | 加入入庫登記、查驗工單、整備紀錄 | 能看見並改善整段前置時間，但需現場人員配合改變作業方式 |
| C. 涵蓋回收全流程 | 從違約判定、派車開始 | 全流程可視化，但範圍大、需與催收單位整合 |

⭐ 建議從 A 開始，並視情況往 B 推進。前置流程的耗時往往佔整體處分時間相當比例，值得後續納入。

❓ **待確認**：這段流程目前怎麼跑？各段大約要多久？主要瓶頸在哪一段？

**上架相關功能**

| 功能 | 說明 |
|---|---|
| 車輛資料的新增 / 編輯 / 刪除 | 刪除建議採「下架封存」而非實際刪除，以保留紀錄 |
| 批次上架 | 一次處理多台 |

### 4.2 車輛資訊與車況檢查

車況資訊的完整度對成交價的影響相當直接。當車商無法確認車況時，通常會將不確定性反映在出價中，因此車況揭露的投入與成交價之間有明顯關聯。

#### 選項比較

| 選項 | 做法 | 成本 | 對成交價的影響 | 爭議發生率 |
|---|---|---|---|---|
| A. 照片 + 自填車況 | 內部人員拍照、勾選車況 | 低 | 基準 | 較高 |
| B. 標準化自檢 + 評級 ⭐ | 依標準表單檢查、給評級、標記傷痕位置 | 中（人力 + 訓練） | 約 +5～10% | 中 |
| C. 第三方檢驗報告 | 委外檢驗機構出具報告 | 高（每台檢驗費） | 約 +10～20% | 較低（責任可部分轉移） |

檢驗費用屬固定成本，對高價車的比例低、對低價車比例高。

⭐ **建議依車價分流**：高於一定價格門檻的車走第三方檢驗，其餘採標準化自檢。

#### 建議提供的車輛資訊

| 類別 | 內容 |
|---|---|
| 基本規格 | 車身號碼、車牌、廠牌、車型、年份、里程、排氣量、燃料、變速箱、驅動方式、顏色、座位數、車主變更次數 |
| 車況評級 | 綜合評分（見下） |
| 車體傷痕圖 | 以車輛示意圖標記每處傷痕的位置與類型（擦傷、凹陷、鏽蝕、需更換等） |
| 照片 | 建議至少 20 張：外觀四角、正背面、左右側、引擎室、行李廂、儀表板（含里程）、前後座、四條輪胎、鑰匙、各處傷痕特寫 |
| 選配 | 引擎啟動影片、引擎聲音、底盤照片 |
| 文件 | 行照、保養紀錄、驗車紀錄、事故紀錄查詢、未繳罰單查詢 |

**關於評級制度**：日本車拍的評分制（S / 5 / 4.5 / 4 / 3.5 / 3 / 2 / R 事故車，內裝另評 A–D）已是亞洲二手車商普遍熟悉的標準。沿用既有制度的好處是車商不需重新學習、也便於與市場行情對照；代價是內部人員需要訓練以維持評級的一致性，評級與實車不符時會成為爭議來源。

❓ **待確認**

- 目前回收車有沒有做車況檢查？誰做？有無標準表單？
- 有哪些可配合的第三方檢驗機構？費用與作業時間？
- **建議直接詢問車商**：決定出價與出價金額時，最看重哪些資訊？在什麼情況下會傾向保守出價？

## 6. 保證金與信用管理

保證金的作用是確保得標者履約付款。若沒有任何機制，出價的約束力較低，得標後未付款的車輛需重新上架，會延長處分時間。

### 6.1 選項比較

| 選項 | 做法 | 優點 | 缺點 |
|---|---|---|---|
| 1. 不收保證金，純靠審核 | 嚴格准入 | 車商門檻最低，參與度最高 | 履約完全依賴審核與後續處置 |
| 2. 年度會員保證金 | 一次繳固定金額，可參與全年拍賣 | 車商負擔小、行政成本低 | 對高價車的保障比例不足 |
| 3. 每台車保證金 | 出價前凍結固定金額或成交價的一定比例 | 保障最直接、對應實際風險 | 車商資金佔用大，會降低同時出價的台數 |
| 4. 信用額度制 ⭐ | 依保證金給予數倍出價額度（例如保證金 50 萬 → 出價額度 500 萬） | 平衡資金效率與風險，額度用完自然形成上限 | 需要清楚說明額度規則 |
| 5. 混合制 | 年度保證金 + 額度制 + 高價車另設門檻 | 最能對應不同風險層級 | 規則較複雜 |

⭐ **建議**：以額度制為基礎，高價車另設額外門檻。

運作方式：車商繳保證金取得數倍出價額度（倍數依信用等級調整）；每筆進行中的最高出價占用額度；得標付款後釋放；額度不足時無法再出價。

### 6.2 違約處理

**階梯式處罰（建議）**

| 違約次數 | 處置 |
|---|---|
| 第 1 次 | 沒收保證金或成交價的一定比例 ❓、停權 30 天 |
| 第 2 次 | 沒收 + 停權 90 天 + 信用降級 |
| 第 3 次 | 永久停權，列入黑名單 |

階梯式的考量是保留車商池規模，同時給予明確可預期的規則；相對的，需要人力管理與追蹤，且對重複違約者仍需搭配關聯性檢查（見 8.3）。

❓ **待確認**：違約金比例訂多少？是否要向違約車商追償重新拍賣的價差？

## 7. 成交後流程

這是初步討論中尚未有具體想法的部分，以下為完整發想。

### 7.1 流程全貌

```
結標
 ↓
① 成交確認     產生成交通知書
 ↓
② 請款         計算應付總額（成交價 + 手續費 + 稅 + 其他費用）
 ↓
③ 付款         車商匯款 → 財務核銷（可扣抵保證金）
 ↓
④ 文件準備     過戶文件、印鑑證明、委任書
 ↓
⑤ 過戶         公司名下 → 車商名下
 ↓
⑥ 交車         車商自取或送車（含鑰匙、行照、備品點交）
 ↓
⑦ 申訴期       一定天數內可提出車況爭議
 ↓
⑧ 結案         帳務沖銷、對應貸款契約結算
```

### 7.2 系統要介入到什麼程度？

| 選項 | 做法 | 取捨 |
|---|---|---|
| A. 純通知 | 系統只發成交通知，其餘全部線下 | 導入成本最低，但無法掌握每台車的進度與責任歸屬 |
| B. 流程追蹤（清單式）⭐ | 每筆成交產生一張交割清單，8 個步驟各有負責人、期限、狀態、附件，逾期自動提醒 | 成本低、效益明確，但需各單位配合更新狀態 |
| C. 全線上 | 串接金流、電子簽章、線上過戶 | 效率最高，但建置成本高、依賴外部單位配合 |

⭐ 建議從 B 開始。掌握「每台車卡在哪一步、卡了幾天」對縮短處分時間的效益相對明顯。

### 7.3 付款時效與方式 ❓

| 議題 | 選項 | 取捨 |
|---|---|---|
| 付款期限 | T+2 / T+3 / T+5 / T+7 工作天 | 期限短則資金回收快、違約可及早發現；期限長則車商籌款壓力小，可能反映在出價上 |
| 付款方式 | 電匯 / 支票 / 保證金抵扣 / 信用額度月結 | 月結對規模較大的車商有吸引力，但公司需承擔信用風險 |
| 逾期處理 | 滯納金（按日計）→ 逾期一定天數視為違約 | 需在嚇阻力與車商接受度之間取得平衡 |
| 是否接受訂金 + 尾款 | —— | 對車商友善，但增加行政作業 |

❓ **待確認**：目前賣車給車商的收款條件是什麼？有無票期、月結的慣例？車商能接受多快付款？

### 7.4 過戶與交車 ❓

| 議題 | 選項 | 取捨 |
|---|---|---|
| 誰跑過戶手續 | (a) 公司代辦（可收費）　(b) 車商自辦　(c) 委託代辦業者 | (a) 進度可掌握，但佔用人力；(b) 成本最低，但進度不可控，車輛可能長期仍登記在公司名下；(c) 折衷 |
| 過戶時點 | (a) 收款後才過戶 ⭐　(b) 過戶與交車同時 | 建議收款後才過戶，以確保價金已收足 |
| 交車方式 | (a) 車商自取　(b) 公司送車（可收費）　(c) 委託物流 | (a) 成本最低；(b)(c) 提升車商便利性但有成本 |
| 逾期未牽車 | 收取停車費 / 逾期一定天數視為棄標 | 需有明確規則，避免車位長期被佔用 |
| 點交項目 | 鑰匙數量、行照、備胎、隨車工具、保養手冊 | 建議訂立標準點交清單並雙方確認 |

車輛售出後的結算關係：

```
成交價                     70 萬
－ 買家手續費（若有，屬公司收入）
－ 拖車費、保管費、整備費、過戶費
＝ 淨回收                  65 萬

貸款未償餘額               90 萬
－ 淨回收                  65 萬
＝ 差額                    25 萬   ← 這 25 萬如何處理？
```

❓ **待確認**

1. 差額是否向原借款人追償？
2. 若成交價高於餘額，超出部分是否退還借款人？
3. 拖車費、保管費、整備費是否可向借款人請求？
4. 是否需要與現有的貸後 / 催收 / 會計系統對接自動沖銷？

**為什麼這題會影響前面的設計**：差額能否追償，會影響底價策略的合理設定範圍。若可追償，公司對較低成交價的接受度較高，可傾向市場邏輯訂價、加快去化；若不可追償，底價需訂得較保守，但同時也較容易面臨長期流標的情況。

### 7.7 爭議、退車與申訴

車商牽車後可能發現與描述不符的情況：里程數不符、事故或泡水未揭露、引擎或變速箱重大瑕疵、車體結構損傷未揭露、證件不齊等。

若沒有明確的處理流程，每件都需個案協商、標準不易一致；同時車商在評估風險時，通常會將這部分不確定性反映在出價中。

**建議的處理架構**（參考日本車拍的申訴制度）

| 要素 | 建議 |
|---|---|
| 申訴期 | 交車後 7–14 天 ❓ |
| 可申訴事由（明列） | 里程不符、事故未揭露、泡水、引擎/變速箱重大故障、證件不符 |
| 不可申訴事由（明列） | 一般消耗品、已揭露的瑕疵、外觀輕微傷痕、主觀不滿意 |
| 舉證責任 | 車商需提出第三方鑑定報告 |
| 處理方式 | 退車全額退款 / 減價補償 / 維修費分攤 / 駁回 |
| 回覆時效 | 平台需在一定工作天內回覆 |
| 紀錄 | 爭議工單、證據、處理歷程、賠償紀錄留存 |

| 建立正式申訴制度的優點 | 缺點 |
|---|---|
| 車商在評估風險時有明確依據，較願意出價 | 需承擔一定的賠償成本 |
| 處理標準一致，減少個案協商 | 需訂立規則與人員訓練 |
| 累積的爭議紀錄可回饋改善車況揭露品質 | 可能有少數車商濫用申訴 |

⭐ 需注意的是，申訴制度屬於事後補救。**較有效的做法是在 4.2 把車況揭露做得完整**，從源頭減少爭議發生。

## 8. 風險與防範

初步討論提到「最後一秒出價」。以下把相關的風險點一併整理，並依影響程度排序。

### 8.1 買方聯合（圍標）

車商私下協議互不競價、輪流得標。這類情況從報表上不容易直接看出，因為拍賣流程表面上是正常運作的，只是成交價偏低。

| 對策 | 有效性 | 副作用 |
|---|---|---|
| 密封投標 | 高 —— 車商無法確認對方是否遵守協議 | 犧牲競價熱度 |
| **隱藏出價者身分** ⭐ | 高 —— 只顯示「出價者 A / B / C」 | 幾乎沒有副作用，成本低 |
| 擴大車商池 | 高 —— 參與者越多越難協調 | 需要時間累積 |
| 得標集中度統計 | 中 —— 少數車商長期集中得標且出價次數偏少時提醒 | 需人工判讀，可能誤判專精特定車種的車商 |
| 輪流得標樣態統計 | 中 | 同上 |
| 隱藏底價 | 中 —— 使聯合方難以精準壓在底價 | 見 3.7 |

⭐ **優先建議：隱藏出價者身分**。成本低、副作用小。

### 8.2 底價資訊的存取控制

底價若在拍賣前被特定車商得知，成交價會傾向落在「底價 + 一個級距」，公司實際上取得的競價溢價會被壓縮，而從一般報表上不容易發現。

| 對策 | 說明 |
|---|---|
| 底價存取權限最小化 | 僅核價主管可查看 |
| 查看與變更都留存紀錄 ⭐ | 建議「查看」也記錄，這是相對關鍵的一項 |
| 樣態統計 ⭐ | 統計「成交價 = 底價 + 1 個級距」的比例，比例明顯偏高時進一步檢視 |
| 職務分離 | 設定底價的人不同時負責聯繫車商 |
| 代理出價上限同樣列為機密 | 見 3.3 |

### 8.3 關係人出價

若公司內部人員或關係人以車商帳號參與出價，會影響拍賣的公正性，也影響車商對平台的信任。

| 對策 |
|---|
| 公司內部人員帳號在系統上直接禁止出價 |
| 車商註冊時做關聯性檢查（同一負責人、同一地址、同一銀行帳戶） |
| 統計「從未得標但經常將價格推至接近底價」的帳號 |
| 出價紀錄不可修改刪除，稽核可查 |
| 明訂員工與關係人不得參與競標的規範 |

### 8.4 得標後未付款

較常見的情況。對策見第 6 章（保證金、額度、階梯式停權、黑名單）。

補充：核准新車商時建議做關聯性檢查，避免以新登記公司重新註冊。

### 8.5 多重帳號

可能用於試探底價、參與聯合行為或規避停權。對策同 8.3 的關聯性檢查，搭配 5.1 的准入審核。

### 8.6 出價誤植

例如金額多打一位數。對策：出價二次確認 + 異常金額提醒。政策面見 5.3。

### 8.7 撤標比例偏高

見 3.9。屬流程面問題，但對車商參與意願有實質影響。

### 8.8 最後一秒出價

見 3.6。自動延長機制即可解決，屬本清單中影響較小、處理也較容易的一項。

### 8.9 車況爭議

見 4.2 與 7.7。若車商普遍對車況描述的可信度有疑慮，會反映在整體出價水準上。

### 風險優先順序總表

| 風險 | 影響程度 | 處理難度 | 建議優先序 |
|---|---|---|---|
| 底價資訊外洩 | 高 | 低（權限 + 紀錄） | 1 |
| 關係人出價 | 高 | 低（系統直接限制） | 2 |
| 得標後未付款 | 高 | 中（需保證金制度） | 3 |
| 車況爭議 | 高 | 中（需揭露標準 + 申訴流程） | 4 |
| 買方聯合 | 高 | 高（不易察覺） | 5（先做成本低的隱藏身分） |
| 撤標比例偏高 | 中高 | 低（流程改善） | 6 |
| 出價誤植 | 中 | 低 | 7 |
| 多重帳號 | 中 | 中 | 8 |
| 最後一秒出價 | 低 | 低 | 9 |

## 9. 通知與報表

### 9.1 通知事件

「出價被超越」是對成交價影響較直接的一則通知 —— 若沒有它，設定代理出價的車商在被超越後通常不會再回訪。

| 通知事件 | 對象 | 重要性 |
|---|---|---|
| 符合訂閱條件的新車上架 | 車商 | 高 |
| **出價被超越** | 車商 | 最高 |
| 即將結標（1 小時 / 10 分鐘前） | 有出價或關注的車商 | 高 |
| 結標時間已延長 | 相關車商 | 中 |
| 得標通知 | 得標車商 | 最高 |
| 未得標通知 | 其他出價者 | 中 |
| 議價邀請（未達底價） | 最高出價者 | 高 |
| 付款提醒 / 逾期提醒 | 得標車商 | 最高 |
| 可牽車通知 | 得標車商 | 高 |
| 內部：無人出價 / 即將流標 | 營運人員 | 高 |
| 內部：異常出價提醒 | 營運 / 稽核 | 高 |

**通知管道**：Email 與站內通知成本最低但即時性有限；簡訊到達率高但有成本；通訊軟體（LINE / WhatsApp 等）在即時性與到達率上表現較好，是車商日常使用的工具。

⭐ 建議初期以 Email + 站內通知確保功能完整，並盡早導入通訊軟體通知 —— 對「出價被超越」這類需要即時反應的通知，管道差異的影響較明顯。

❓ **待確認**：車商平常用什麼方式聯絡？是否習慣查看 email？

### 9.2 營運報表

- 上架 / 成交 / 流標統計（依期間、車型、價格帶）
- 成交價分布，以及成交價與底價、市場估值的對照
- **平均處分天數，並分段呈現**：入庫→上架、上架→成交、成交→交車（用以定位瓶頸所在）
- 車商參與度、得標集中度
- 違約、爭議、撤標統計

### 9.3 財務報表

- 回收率（成交價 ÷ 貸款餘額）
- 差額認列彙總
- 買家手續費收入（若採用）
- 處分成本明細（拖車、保管、整備、過戶）

### 9.4 內控報表

| 報表 | 用途 |
|---|---|
| 「成交價 = 底價 + 1 級距」的比例 | 見 8.2 |
| 得標集中度異常 | 見 8.1 |
| 帳號關聯性提醒 | 見 8.3 |
| 撤標率 | 見 3.9 |
| 底價存取紀錄 | 稽核用 |

### 9.5 歷史資料的回饋運用

累積的成交資料可以回過來支援定價判斷。上架時系統可顯示：

> 同款、同年份、里程相近的車，過去 6 個月共成交 8 台，成交價中位數 XX 萬，平均 12 天售出。

這能讓底價設定從個人經驗轉為有資料依據，也降低對特定人員的依賴；同時可以量化「哪一種拍賣型態對哪一類車較有效」。限制是需要一段時間累積資料才有參考價值，資料量少時可能誤導。

⭐ **需要提早注意的一點**：即使初期不做這類分析，車輛規格、車況評級、成交價、處分天數等資料**建議從第一天就以結構化方式記錄**。若這些資訊只存在自由填寫的備註欄中，後續較難進行分析，且不易事後補齊。

## 10. 商業模式考量 ❓

目前定位為內部處分工具，但以下兩點建議提早釐清，因為會影響整體規劃方向。

### 10.1 是否收取買家手續費

車輛拍賣業界常見做法是向買方收取成交價的 3–5%。

| 選項 | 取捨 |
|---|---|
| A. 不收 | 規則單純，車商成本較低；平台營運成本由公司吸收 |
| B. 收 3–5% | 產生獨立收入來源，且符合車商既有認知；但車商通常會將手續費計入落地總成本，因此部分會反映在出價金額上 |

### 10.2 是否未來開放外部賣方寄售

| 選項 | 取捨 |
|---|---|
| A. 純內部工具 | 範圍單純；但車輛數量有限，車商回訪頻率與競價熱度較難維持 |
| B. 未來開放其他金融機構 / 租賃公司寄售 | 車輛供給量增加 → 車商回訪頻率提高 → 競價熱度上升，對自家車輛的成交價也有幫助；同時產生手續費收入。代價是需處理多賣方的權限、分潤與對帳，且涉及同業間的合作關係 |

⭐ 這一點值得管理層提早討論。拍賣平台的競價效果與參與車商的活躍度直接相關，而活躍度又與可選車輛的數量有關。若長期只有自家車輛且數量有限，需要另外思考如何維持車商的回訪意願。

### 10.3 其他可能的收入來源

- 車商年費 / 會員費
- 加值服務：物流送車、車況鑑定、車商採購融資

## 11. 導入順序建議

依「投入成本與預期效益」排序，供規劃參考。

### 第一階段 —— 能完整跑完一次拍賣

| 項目 | 理由 |
|---|---|
| 車輛上架與管理（含標準化車況表單與評級） | 基礎功能；車況品質與成交價關聯明顯 |
| 定時開標 + 隱藏底價 + 出價級距 | 最通用、車商門檻最低 |
| 自動延長（結標規則） | 成本低、效益明確 |
| 代理出價 | 提升參與度效益較高 |
| 車商註冊 + 人工審核 | 履約風險的第一道把關 |
| 瀏覽、篩選、我的競標 | 基本體驗 |
| 交割清單（成交後流程追蹤） | 成本低，對處分時間改善明顯 |
| 通知：出價被超越、得標、付款提醒 | 這三則的效益高於其他通知 |
| 底價存取控制 + 操作紀錄 | 建議不要延後，後補成本較高 |
| 基本成交 / 流標報表 | 用於後續調整策略 |
| 隱藏出價者身分 | 成本極低，見 8.1 |

### 第二階段 —— 提升成交價與成交率

- 密封投標型態
- 流標後議價機制
- 保證金 / 信用額度制度
- 媒合訂閱通知
- 車商主帳號 + 子帳號 + 額度控管
- 通訊軟體通知
- 爭議申訴工單
- 車商分級與履約評分
- 內控報表（得標集中度、底價命中率）
- 上架時顯示同款車歷史成交參考

### 第三階段 —— 規模化

- 即時同步拍（含預先出價）
- 第三方檢驗整合
- 線上付款
- 物流與交車整合
- 完整申訴與仲裁制度
- 買家手續費與發票
- 對外開放賣方寄售
- 與貸後 / 催收系統整合
