# 一、需求背景

車輛違約回收後採密封投標方式賣給 3–5 家長期合作的二手車廠商，廠商在出價前會親自看實車。本系統為廠商端站台，提供查看邀標車輛、出價、修改出價，以及查看已得標車輛。廠商以內部開通的帳號密碼登入，**不開放註冊**。

---

# 二、規則與資訊揭露

|名詞|定義|
|---|---|
|第一輪拍賣|全體廠商可見，起標價 0 元|
|加價輪|僅被內部勾選的廠商可見並具出價資格。起標價＝前一輪最高出價（前一輪無人出價時為 0 元）|
|有效出價|廠商在該輪內最後一次送出的金額|

|規則|說明|
|---|---|
|出價下限|第一輪：≥ 0 元。加價輪：必須高於該輪起標價|
|修改出價|截止前可修改、次數不限，**可調降**但仍須符合出價下限；以最後一次送出的金額為準|
|截止判定|以伺服器時間為準（JST），截止後送出一律拒絕，不設寬限期、不自動延長。前端倒數以伺服器時間校正|
|同時多台|常態會有多台車同時在拍賣|
|幣別與格式|日幣，無金額上限，顯示千分位|

## 2.1 資訊揭露

|廠商可見|廠商不可見／不呈現|
|---|---|
|自己本輪的有效出價|其他廠商的出價金額、廠商身分、邀請名單|
|加價輪的起標價（＝前一輪最高出價）|本輪目前最高價、目前出價家數、自己是否為目前最高價|
|自己得標車輛的成交金額|內部參考價、貸款餘額、借款人個資、個人資訊類附件|
|—|自己的歷史出價、過往拍賣紀錄|

# 四、登入與密碼

|項目|規則|
|---|---|
|入口|**Email + 密碼**。Email 即登入帳號|
|帳號來源|不開放註冊，由內部系統「廠商管理」新增廠商時一併開通（見內部文件第六章）|
|帳號粒度|一家廠商一個帳號，多人共用（不做主／子帳號）|
|停用廠商|內部將廠商停用後**無法登入**；已送出的出價仍保留於內部端排名|
|未登入|不揭露任何車輛資訊，一律導向登入頁|

**重設密碼**採最簡單可行的做法，不做額外的安全強化設計：

- 廠商自助：登入頁「忘記密碼」→ 輸入 Email → 寄送 Email 重設連結 → 設定新密碼。連結有效期限依系統慣例
- 內部代為重設：內部在 portal「廠商管理」點「重設密碼」，系統重發新密碼給廠商
- 登入後可自行修改密碼；**首次登入不強制修改密碼**，密碼複雜度沿用既有慣例

# 五、拍賣列表

## 5.1 可見範圍與卡片

第一輪拍賣：投標中的全部可見。加價輪：僅被內部勾選的廠商可見。已結標、已決標的拍賣不出現在此列表；無可出價的拍賣時顯示 empty component。

以卡片列表呈現，點擊進入車輛詳細頁。卡片內容：

|元素|說明|
|---|---|
|車輛照片|首張照片作為縮圖，無照片時顯示 placeholder|
|車輛簡要資訊|廠牌／車型、年份、里程、顏色。里程為內部收車後填寫的**實際里程**（單一數值），非進件的區間值|
|拍賣時間|起訖日 + 剩餘時間倒數|
|起標價|第一輪顯示 0 元；加價輪顯示起標價金額|
|我的出價狀態|「未出價」／「已出價：金額」（本輪）|
|輪次標記|加價輪的卡片加上標記|

## 5.2 篩選、排序與載入

|項目|規則|
|---|---|
|篩選條件|**依卡片呈現的車輛資料**（廠牌／車型、年份、里程、顏色），**再加上「是否出價」**（未出價／已出價）|
|排序|不提供使用者自訂排序；**預設剩餘時間最短優先**（最快截止的排最前）|
|載入方式|**無限滾動**，不做分頁|
|手機端|篩選收在「篩選」按鈕後的抽屜（drawer）中|

「我的拍賣」與「已得標」共用同一套篩選元件，其中「是否出價」在該兩個列表不適用。

# 六、車輛詳細頁與出價

## 6.1 詳細頁內容

|區塊|內容|
|---|---|
|照片|車輛照片、車輛檢查表（前／後／左／右）、走行距離メーター等車輛部位照片，可滑動／放大檢視|
|車輛完整資料|沿用內部系統的車輛資料欄位（欄位與日文標籤見內部文件 4.3）。其中**走行距離、次回車検日、自賠責保険の有効期限**為內部收車後更新的現況值，非進件值。內部參考價（車両価格範囲、車両評価）不呈現|
|備註|內部填寫的說明事項，無內容時不顯示此區塊|
|其他附件|內部上傳的車輛相關附件，含收車後的現況照片與線下取得的評分表。圖片與 pdf 皆採**站內內嵌預覽**|
|拍賣資訊|輪次類型、起訖日、剩餘時間倒數、起標價|
|我的出價|本輪已出價時，顯示金額與出價時間|
|出價按鈕|主要按鈕，手機端固定於畫面底部（sticky）|

**資料範圍與穩定性**：附件範圍以內部文件 4.4.1 的白名單為準，**車検証、自動車保険証券、運転免許証の写真、個人情報添付等一律不呈現**。車輛資料、備註與附件於**排定拍賣前由內部定版**，拍賣進行中內部不可編輯、不可增刪附件，廠商在整個投標期間看到的標的資料不會變動。

## 6.2 出價與修改出價

```
點「出價」→ 輸入金額 → 點「確認」→ 二次金額確認 → 確認 → 出價成功
```

|項目|規則|
|---|---|
|金額輸入|單一金額欄位，顯示該輪起標價與下限提示|
|校驗|① 必填、僅數字、正整數 ② 符合該輪出價下限 ③ 拍賣須在進行中 ④ 廠商須具備該輪出價資格|
|二次確認|彈窗以大字顯示金額，提供「返回修改」與「確認出價」|
|成功|回到詳細頁，按鈕變為「修改出價」，顯示目前出價金額|
|失敗|依原因提示（未達下限／已截止／無資格／網路異常）|
|修改出價|已出價者按鈕為「修改出價」，預帶本輪目前金額；校驗同上，**可調降**但不得低於出價下限；截止前不限次數，同樣需二次確認|

**加價輪的差異**：僅被內部勾選的廠商可見；起標價＝前一輪最高出價並明確顯示於詳細頁，出價必須高於起標價；第一輪未出價的廠商若被勾選，仍可在加價輪出價。

# 七、我的拍賣 / 已得標

兩個列表皆與拍賣列表共用卡片元件。

|列表|內容|差異|移除時機|
|---|---|---|---|
|我的拍賣|該廠商有出價的進行中標的|卡片顯示「我的出價：金額」；進入詳細頁後按鈕為「修改出價」|該輪結標後移除|
|已得標|該廠商已得標的拍賣|卡片顯示成交金額與得標日期；詳細頁為車輛完整資料、附件、成交金額，無出價按鈕|付款與過戶為線下流程，內部在 portal 點「完成」後不再顯示|

未得標的拍賣不在站上呈現，以通知告知（見 8.2 第 5 項）。

# 八、通知

## 8.1 通知中心

入口為導覽列「通知」，顯示通知標題、內文、時間、關聯拍賣連結，依時間新到舊排序。

- **未讀呈現**：導覽列入口顯示未讀數 badge，列表中未讀項目加標記
- **已讀時機**：**點開該則訊息即標記為已讀**，不另提供「標記已讀」按鈕
- 不提供「標記全部已讀」、不提供刪除；通知不設保留期限，全部保留

## 8.2 通知事件

管道為 **Email + SMS + 站內通知中心**，三者同時發送，一律以**日文**發送。SMS 收件號碼取自內部系統「廠商管理」的電話欄位。訊息模板文案待定，實作前需補齊。

|# |事件|收件對象|觸發|
|---|---|---|---|
|1|新的拍賣（第一輪已排定）|全體廠商|內部「排定拍賣」submit 成功|
|2|加價拍賣邀請|被內部勾選的廠商|內部「進入加價拍賣」submit 成功。可帶入車輛資訊、本輪起標價、本輪截止日、拍賣連結|
|3|即將截止（催投）|**僅該輪尚未出價的廠商**|① 系統自動：結標日前 2 天 09:00（JST）發送一次 ② 內部手動觸發，不限次數（詳見內部文件 5.2.2）|
|4|得標|得標廠商|內部「決標」或「指定成交廠商」成功|
|5|未得標|該輪其他具出價資格的廠商|同上。不含金額與名次，例：「order:xxxx 抱歉您未得標」|
