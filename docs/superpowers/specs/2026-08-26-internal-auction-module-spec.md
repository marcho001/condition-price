# 一、需求背景

車輛違約回收入庫後需要盡快去化。買方為 3–5 家長期合作的二手車廠商，出價前會親自看實車。銷售方式為**密封投標**：廠商在期限內各自出價，截止後由內部開標，不設底價。若內部認為價格偏低或出現同價，可發起加價輪再次徵求出價，輪數不限。

本期在既有內部 portal（xstar-web-pc）新增拍賣模組，涵蓋「收到車 → 排定拍賣 → 開標 → 決標／加價輪」。上游違約回收與下游收款、過戶、交車為線下流程。廠商出價的對外站台另起專案，後端拍賣核心與資料共用。

# 二、名詞與規則

|名詞|定義|
|---|---|
|第一輪拍賣|由「排定拍賣」發起的首次投標。全體廠商可見，起標價 0 元|
|加價輪|前一輪結標後由內部發起的下一輪投標。僅被勾選的廠商可見並具出價資格|
|輪次|同一台車的第幾次投標，第一輪為第 1 輪，之後累加|
|起標價|該輪出價下限的基準。第一輪為 0 元；加價輪＝前一輪最高出價（前一輪無人出價時為 0 元）|
|結標／決標|結標＝該輪截止時間到達、投標關閉；決標＝內部指定得標廠商，訂單進入「已決標」|
|有效出價|廠商在該輪內最後一次送出的金額|

|項目|規則|
|---|---|
|出價下限|第一輪：≥ 0 元。加價輪：**必須高於**該輪起標價|
|修改出價|截止前可修改、次數不限，以最後一次送出的金額為準|
|排名|依該輪有效出價金額由高到低|
|同價|最高出價兩家以上並列時，「決標」disable，改走「指定成交廠商」或「進入加價拍賣」|
|無人出價|最高出價顯示為空，「決標」disable，可「進入加價拍賣」重新徵求，起標價 0 元|
|截止判定|以伺服器時間為準（JST）。截止後送出一律拒絕，不設寬限期、不自動延長|
|幣別與格式|日幣，無金額上限，顯示千分位|

# 四、車輛管理

## 4.1 車輛進入列表的方式

```
收車人員在 order 上一鍵呼叫 API 變更訂單狀態
        ↓
該訂單的車輛出現在「車輛管理」列表，狀態＝待排定拍賣，並沿用進件時填寫的車輛資料
```

車輛資料以進件資料為底，本模組不重新輸入；僅「會因使用時間而改變」的欄位可更新為收車後現況（見 4.4）。**更新內容一律不寫回 order**，另存於本模組（實作方式見 10.2）。訂單狀態值與取資料 API 見 10.1。

## 4.2 列表

**欄位**：orderNo｜車牌｜廠牌／車型｜年份｜顏色｜收車日（訂單狀態變更為已收車的日期）｜狀態（待排定拍賣）｜操作

- 操作：「車輛詳細」、「排定拍賣」
- **列表不顯示里程**，里程於「車輛詳細」彈窗呈現與更新
- 需分頁（在架車輛預估不超過 100 台）。篩選、排序與分頁規則見第七章

## 4.3 車輛資料欄位

沿用進件既有的「車両情報」定義，不另行新增。全部欄位於「車輛詳細」彈窗與對外站車輛詳細頁呈現（列表僅顯示 4.2 的欄位）。

**「收車後可編輯」**＝該欄位會隨車輛被繼續使用而改變，開放內部更新為現況；其餘一律唯讀，以進件資料為準。

|欄位 key|日文標籤|中文標籤|對外站|收車後可編輯|
|---|---|---|---|---|
|makeName|メーカー|制造商|呈現|唯讀|
|seriesName|車系|车系|呈現|唯讀|
|yearName|モデル|车型|呈現|唯讀|
|modelName|グレード|车款|呈現|唯讀|
|carYear|年式|生产年份|呈現|唯讀|
|color|ボディカラー|车身颜色|呈現|唯讀|
|fuelType|燃料の種類|燃料类型|呈現|唯讀|
|displacement|総排気量または定格出力|排量|呈現|唯讀|
|**mileage**|走行距離|公里数|呈現（實際里程，非區間值）|**可編輯**|

|licensingPlateNumber|ナンバープレート|车牌号码|呈現|唯讀|

|**trafficInsuranceExpiryDate**|自賠責保険の有効期限|交强险失效日|呈現|**可編輯**|

- 缺值顯示「—」或 `NA`，沿用既有慣例
- **走行距離**：進件為區間值（例：3 萬 ~ 5 萬 km），**不對外呈現**；收車後由內部填寫實際里程（單一數值，km），**排定拍賣前必填**，未填時「排定拍賣」disable
- **備註**：本模組新增的自由文字欄位（非必填），供補充進件欄位涵蓋不到的說明（例：收車時發現的碰撞痕、內裝狀況、備品缺件）

## 4.4 操作 —— 「車輛詳細」彈窗

> **背景**：進件與收車之間隔了一段違約處理期間，車輛仍持續被使用。里程一定不是進件當時的數字，車況與外觀也可能改變。因此本彈窗除附件外必須完整列出車輛資料，並開放內部更新為收車後的現況，作為對外拍賣的依據。

|區塊|內容|
|---|---|
|標頭|orderNo、車牌（識別用）|
|車輛資料|4.3 全部欄位。標示「可編輯」者可就地更新，其餘唯讀|
|附件|列出該車附件（範圍見 4.4.1），圖片可放大檢視、pdf 可預覽；下方提供上傳，用途包含收車後的現況照片、線下向廠商取得的評分表|

**收車現況的處理原則**

- 收車後拍攝的照片一律以「上傳新附件」加入，**不覆蓋進件照片**
- 更新內容**不寫回 order**，另存於本模組；order 的進件資料維持原樣
- 顯示時該欄位有現況值則以現況值為準，否則回落至進件值
- 每次更新留存欄位、前後值、操作人、時間

### 4.4.1 附件範圍

下列為本模組顯示且對外站呈現的**全部**附件類型，未列於此者一律不顯示、不呈現：

- 車輛照片（進件上傳）
- 車両チェックシート（前／後／左／右）
- 走行距離メーター照片
- 1列目シート／2列目シート／エンジン写真等車輛部位照片
- 本模組上傳的附件（收車現況照片、評分表、其他）

排除的包含（但不限於）：**車検証、自動車保険証券**、運転免許証の写真、個人情報添付（身分証明書、収入証明書、社会保険証明書、源泉税証明書、銀行資金証明書、個人納税証明書、不動産証明書）。車検証與自動車保険証券載有所有者・使用者的氏名與住所，屬借款人個資，本期一律不公開。

### 4.4.2 上傳規則

支援 jpg / jpeg / png / pdf，張數不限、可多次上傳，單檔大小依系統慣例。清單顯示檔名、上傳人、上傳時間、預覽、刪除。對外可見性依 4.4.1 一體適用，不提供逐檔開關。

### 4.4.3 可編輯期間

|狀態|車輛資料（含備註）|附件上傳／刪除|
|---|---|---|
|待排定拍賣|可編輯（限 4.3 標示可編輯的欄位）|可上傳、可刪除|
|拍賣進行中|唯讀|**不可上傳、不可刪除**|
|已結標／已決標／已完成|唯讀|唯讀|

車輛資料與附件**於排定拍賣前定版**。拍賣進行中鎖定的理由是廠商已依現有資料出價，投標期間變動標的資料會影響出價基礎；線下取得的評分表等資料須於排定拍賣前收集完成。

## 4.5 操作 —— 「排定拍賣」彈窗

|欄位|必填|預設值|規則|
|---|---|---|---|
|拍賣開始日|是|今日|不可早於今日|
|拍賣結束日|是|今日 + 7 日|必須晚於開始日|

時間精度**到日**、時區 JST（今日為 2026/8/26 時預設帶入 2026/8/26 ~ 2026/9/2）。排定後**不提供**修改起訖日、提前結束或延長。第一輪邀請對象為全體廠商，不需勾選。

```
填寫日期範圍 → 點「確認」 → 二次確認 → submit
```

- **前置檢核**：走行距離（實際里程）未填寫時不可送出
- **二次確認**：唯讀呈現 ① orderNo、車牌 ② 拍賣起訖日 ③ 車輛資料全欄位（含已更新的現況值與備註）與 4.4.1 範圍內的附件。此畫面**一律不可編輯**，需修改請返回「車輛詳細」彈窗
- **submit 成功後**：① 訂單從車輛管理移除，轉入「拍賣管理 → 拍賣進行中」 ② 建立第 1 輪拍賣，起標價 0 元 ③ 對外站同步出現這台車，全體廠商可見 ④ 觸發廠商通知（見第八章）

# 五、拍賣管理

## 5.1 三個 tab 與狀態流轉

|tab|內容|可見權限|
|---|---|---|
|拍賣進行中|投標期間內的拍賣，含第一輪與加價輪|拍賣營運、決標管理|
|已結標|已到截止日、尚未決標|僅決標管理|
|已決標|已決標的訂單|僅決標管理|

```
待排定拍賣 ──排定拍賣──▶ 投標中（第 1 輪）──截止──▶ 已結標
（車輛管理）                                          │
                       ┌──進入加價拍賣───────────────┤
                       ▼                              ▼
                投標中（第 N 輪）──截止──▶ 已結標 ──決標／指定成交廠商──▶ 已決標 ──完成──▶ 已完成
                                                                                   （不在任何列表呈現）
```

## 5.2 拍賣進行中

**欄位**：orderNo｜車輛資料（車牌、廠牌／車型、年份、里程、顏色）｜輪次｜起訖日期｜剩餘時間｜**已出價家數**｜操作

- 剩餘時間依伺服器時間倒數，結束後自動轉入「已結標」
- **截止前，列表與彈窗一律不顯示出價金額**，僅顯示家數與各廠商是否已出價
- 操作：「車輛詳細」、「催投」

### 5.2.1 「車輛詳細」彈窗

內容同 4.4（車輛資料 + 附件），另加該輪拍賣資訊：輪次、起訖日、剩餘時間、起標價、已出價家數、各廠商是否已出價（僅狀態，不含金額）。此階段**全部唯讀**（見 4.4.3）。

### 5.2.2 「催投」

對該輪具出價資格且尚未出價的廠商發出即將截止通知，管道為 Email + SMS + 對外站站內通知（模板見第八章）。

|觸發|規則|
|---|---|
|自動|該輪**結標日前 2 天的早上 09:00（JST）自動發送一次**，同一輪限 1 次。發送當下重新計算未出價名單，已出價者不會收到|
|手動|內部可另行觸發，不限次數|
|例外|排定當下距結標已不足 2 天（例：起訖日僅 1 天）時不發自動催投，僅能手動|

## 5.3 已結標

拍賣結束後由「拍賣進行中」自動轉入。

**欄位**：orderNo｜車輛資料｜輪次｜起訖日期｜最高出價（無人出價時為空）｜結標日｜操作（「詳細」）

### 5.3.1 「詳細」彈窗

顯示車輛摘要、輪次、該輪起訖日與起標價，並列出該輪具出價資格的**全部**廠商：名次（依金額高到低）、廠商名稱、出價金額（未出價者顯示「未出價」）、出價時間；最高價並列時於各列標示同價。無人出價時，出價列表以 empty component 佔位。

|操作|行為|disable 條件|
|---|---|---|
|決標|決標給最高出價廠商，訂單轉入「已決標」|無人出價，或最高出價兩家以上並列|
|指定成交廠商|由內部從**最高價並列的廠商**中選定一家成交，訂單轉入「已決標」|最高出價未出現並列（含無人出價、僅一家最高價）|
|進入加價拍賣|開啟「加價拍賣設定」彈窗（見 5.4）|無|

兩者皆需二次確認（顯示成交廠商與金額），成功後觸發得標／未得標通知。

**「指定成交廠商」規則**：本版新增流程，用途單一 —— 在同價僵局下直接擇一成交，作為「進入加價拍賣」之外的另一條出口。**僅限最高出價同價時使用**，可選對象**僅限最高價並列的廠商**（未出價、非最高價者皆不可指定），**成交金額等於該廠商的出價金額**（內部不可輸入或調整），**不需填寫指定理由**。

## 5.4 「進入加價拍賣」彈窗

|欄位|必填|預設值|規則|
|---|---|---|---|
|拍賣開始日／結束日|是|今日 / 今日 + 7 日|與 4.5 同規則|
|廠商勾選|是（至少一家）|**全部勾選**|僅被勾選的廠商會收到通知並取得出價資格，未勾選者看不到此拍賣|

submit 後：訂單退回「拍賣進行中」，輪次 ＋1，起標價＝前一輪最高出價（前一輪無人出價時為 0 元），本輪出價必須高於起標價；對被勾選的廠商發出加價拍賣通知。**前一輪資料保留不覆蓋**，每輪各自留存起訖日、邀請名單、起標價、各家出價與時間。

輪數不限：每輪結標後都可在「已結標」的詳細彈窗中三選一（決標 / 指定成交廠商 / 再進入加價拍賣）。無人出價的拍賣同樣透過此流程重新徵求出價。

## 5.5 已決標與「完成」

**欄位**：orderNo｜車輛資料｜得標廠商｜成交金額｜決標輪次｜決標方式（決標／指定成交廠商）｜決標日期／操作人｜操作

操作為「詳細」（唯讀，含各輪出價紀錄）與「完成」。

付款與過戶為線下流程，線下完成後由內部點「完成」（二次確認）標記結案，系統不驗證款項與過戶狀態。標記完成後：

- 該筆訂單**自「已決標」列表移除**，不新增第四個 tab、不提供「已完成」篩選條件
- 資料不刪除，狀態標記為「已完成」，保留稽核紀錄
- 對外站「已得標」列表不再顯示該筆

# 六、廠商管理

拍賣廠商為獨立的一批主檔，於本模組建檔，**不沿用既有的販売業者主檔**。

|欄位|必填|說明|
|---|---|---|
|廠商名稱／聯絡人／電話|是|電話同時作為 SMS 通知的收件號碼|
|Email|是|通知寄送對象，**同時作為對外站登入帳號**|
|啟用／停用|是|預設啟用|
|備註|否|自由文字|

- **操作**：新增（建立主檔並同步開通對外站帳號）、編輯、停用／啟用（不刪除資料）、重設密碼（重發對外站帳號密碼）
- **帳號**：**一家廠商一個帳號**，不支援單一廠商多帳號；以 Email 為登入帳號，新增廠商時一併開通
- **權限與核准**：拍賣營運與決標管理皆可完整操作，不另設權限；名單增減**不需核准流程**
- **停用的效果**：不再收到通知、不出現在加價輪勾選名單、無法登入對外站
- **對進行中拍賣的影響**：拍賣期間新增的廠商不追加至已開始的輪次，自下一輪起才具出價資格；拍賣期間停用的廠商，已送出的出價保留並列入排名，但不再收到催投與後續通知

# 八、通知

管道為 **Email + SMS**，同時於對外站登入後可看到站內通知。**訊息模板文案待定，實作前需補齊**；訊息不提供內部在送出前編輯。

|# |事件|收件對象|備註|
|---|---|---|---|
|1|第一輪拍賣已排定|全體廠商|—|
|2|加價拍賣邀請|被勾選的廠商|可帶入車輛資訊、本輪起標價、本輪截止日、拍賣連結|
|3|即將截止（催投）|該輪尚未出價的廠商|觸發規則見 5.2.2|
|4|得標|得標廠商|—|
|5|未得標|該輪其他具出價資格的廠商|不含金額與名次。例：「order:xxxx 抱歉您未得標」|

**語言**：內部 portal 介面為中文、日文（沿用 portal 現行多語系機制，不另做設計）；**對外站介面與寄送給廠商的通知一律日文**。
