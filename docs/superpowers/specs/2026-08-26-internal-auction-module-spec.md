# 一、需求背景

車輛違約回收入庫後需要盡快去化。買方為 3–5 家長期合作的二手車廠商，廠商在出價前會親自看實車。銷售方式為密封投標：廠商在期限內各自出價，截止後由內部開標；不設底價。若內部認為價格偏低或出現同價，可發起加價輪再次徵求出價，輪數不限。

本期在既有內部 portal（xstar-web-pc）新增拍賣模組，涵蓋「收到車 → 排定拍賣 → 開標 → 決標／加價輪」。上游違約回收與下游收款、過戶、交車為線下流程。

廠商出價的對外站台另起專案，後端拍賣核心與資料共用。

# 二、名詞與規則定義

|名詞|定義|
|---|---|
|第一輪拍賣|由「排定拍賣」發起的首次投標。全體廠商可見，起標價 0 元|
|加價輪|前一輪結標後由內部發起的下一輪投標。僅被勾選的廠商可見並具出價資格|
|輪次|同一台車的第幾次投標。第一輪為第 1 輪，之後依序累加|
|起標價|該輪出價下限的基準。第一輪為 0 元；加價輪為前一輪的最高出價金額（前一輪無人出價時為 0 元）|
|結標|該輪拍賣截止時間到達，投標關閉|
|決標|內部指定得標廠商，該筆訂單進入「已決標」|
|有效出價|廠商在該輪內最後一次送出的金額|

## 2.1 出價與排名規則

|項目|規則|
|---|---|
|出價下限|第一輪：出價金額 ≥ 0 元。加價輪：出價金額**必須高於**該輪起標價|
|修改出價|截止前可修改，次數不限，以最後一次送出的金額為有效出價|
|排名|依該輪有效出價金額由高到低|
|同價|最高出價有兩家以上並列時，「決標」按鈕 disable。可透過「指定成交廠商」或「進入加價拍賣」處理|
|無人出價|該輪最高出價顯示為空，「決標」按鈕 disable。可透過「進入加價拍賣」重新徵求出價，起標價為 0 元|
|截止判定|以伺服器時間為準（日本時區），截止後送出的出價一律拒絕，不設寬限期、不做自動延長|
|幣別與格式|日幣，無金額上限，顯示千分位|

# 四、車輛管理

## 4.1 車輛進入列表的方式

```
收車人員確認收到車
        ↓
在 order 上一鍵呼叫 API 變更訂單狀態
        ↓
該訂單的車輛出現在「車輛管理」列表，狀態＝待排定拍賣
        ↓
車輛資料沿用該訂單進件時填寫的資料
```

|項目|說明|
|---|---|
|觸發來源|收車人員在 order 上的一鍵操作，透過 API 變更訂單狀態|
|資料來源|沿用進件時填寫的車輛資料，本模組不重新輸入、不開放編輯|
|訂單狀態值與取資料 API|待確認（見 8.1）|

## 4.2 列表欄位

|欄位|說明|
|---|---|
|orderNo|訂單編號|
|車牌|進件資料|
|廠牌／車型|進件資料|
|年份|進件資料|
|里程|進件資料|
|顏色|進件資料|
|收車日|訂單狀態變更為已收車的日期|
|狀態|待排定拍賣|
|操作|「附件」、「排定拍賣」|

分頁：需要（在架車輛預估不超過 100 台）。篩選與排序條件見 8.2。

## 4.4 操作 —— 「附件」彈窗

彈窗內容為**車輛相關附件的檢視與上傳**，不重複呈現列表已有的車輛資料。

|區塊|內容|
|---|---|
|標頭|orderNo、車牌（識別用）|
|附件清單|列出該訂單目前的車輛相關附件，圖片可放大檢視、pdf 可預覽|
|上傳新附件|彈窗下方提供上傳功能，用途包含內部人員線下向廠商取得的評分表|

### 4.4.1 附件範圍

**個人資訊類附件不出現在本模組的任何畫面**，也不對廠商公開。

|附件類型|本模組顯示|對外站呈現|

|走行距離メーター照片|顯示|呈現|
|1列目シート／2列目シート／エンジン写真等車輛部位照片|顯示|呈現|

### 4.4.2 上傳規則

|項目|規則|
|---|---|
|支援格式|圖片（jpg / jpeg / png）、pdf|
|張數|不限，可多次上傳|
|單檔大小上限|依系統慣例|
|清單資訊|檔名、上傳人、上傳時間、預覽、刪除|
|對外可見性|依 4.4.1，不提供逐檔開關|

## 4.5 操作 —— 「排定拍賣」彈窗

|欄位|必填|預設值|規則|
|---|---|---|---|
|拍賣開始日|是|今日|不可早於今日|
|拍賣結束日|是|今日 + 7 日|必須晚於開始日|

|項目|說明|
|---|---|
|時間精度|**到日**，時區為日本時區（JST）|
|預設值範例|今日為 2026/8/26 時，預設帶入 2026/8/26 ~ 2026/9/2|
|排定後修改|**不提供**修改起訖日、提前結束、延長|
|第一輪邀請對象|全體廠商，不需勾選|

### 4.5.1 操作流程

```
填寫日期範圍 → 點「確認」 → 二次確認 → submit
```

|步驟|內容|
|---|---|
|二次確認|顯示車輛（車牌／orderNo）與拍賣起訖日，確認後送出|
|submit 成功後|① 該筆訂單從車輛管理移除，轉移至「拍賣管理 → 拍賣進行中」<br>② 建立第 1 輪拍賣，起標價 0 元<br>③ 對外站同步出現這台車，全體廠商可見<br>④ 觸發廠商通知（模板待定，見第六章）|

# 五、拍賣管理

## 5.1 三個 tab

|tab|內容|可見權限|
|---|---|---|
|拍賣進行中|投標期間內的拍賣，含第一輪與加價輪|拍賣營運、決標管理|
|已結標|已到截止日、尚未決標的拍賣|僅決標管理|
|已決標|已決標的訂單|僅決標管理|

## 5.2 拍賣進行中

### 5.2.1 列表欄位

|欄位|說明|
|---|---|
|orderNo|訂單編號|
|車輛資料|車牌、廠牌／車型、年份、里程、顏色|
|輪次|第 N 輪|
|起訖日期|拍賣開始日 ~ 結束日|
|剩餘時間|依伺服器時間倒數，倒數結束後自動轉入「已結標」|
|**已出價家數**|該輪已出價的廠商家數（不顯示金額）|
|操作|「附件」、「催投」|

截止前，列表與彈窗一律不顯示出價金額。

### 5.2.2 操作 —— 「附件」彈窗

內容同 4.4（附件清單與上傳），另加該輪拍賣資訊：輪次、起訖日、剩餘時間、起標價、已出價家數、各廠商是否已出價（僅狀態，不含金額）。

投標中是否開放上傳新附件見 8.3。

### 5.2.3 操作 —— 「催投」

對該輪尚未出價的廠商發出即將截止通知。

|項目|說明|
|---|---|
|對象|該輪具出價資格且尚未出價的廠商|
|觸發方式|手動觸發；是否另加自動觸發（截止前 N 日）待確認（見 8.4）|
|通知管道|Email + SMS + 對外站站內通知|
|模板|待定（見第六章）|

## 5.3 已結標

拍賣結束後，訂單自動由「拍賣進行中」轉移到「已結標」。

|欄位|說明|
|---|---|
|orderNo|訂單編號|
|車輛資料|車牌、廠牌／車型、年份、里程、顏色|
|輪次|第 N 輪|
|起訖日期|該輪起訖日|
|最高出價|該輪最高有效出價金額；無人出價時為空|
|結標日|該輪截止日|
|操作|「詳細」|

## 5.4 已結標 —— 「詳細」彈窗

列出所有廠商以及他們的出價。

|欄位|說明|
|---|---|
|名次|依金額由高到低|
|廠商名稱|該輪具出價資格的廠商全部列出|
|出價金額|該輪有效出價；未出價者顯示「未出價」|
|出價時間|最後一次送出的時間|
|同價標記|最高價並列時，於並列各列標示|

無人出價時，出價列表以 empty component 佔位。彈窗同時顯示車輛摘要、輪次、該輪起訖日、該輪起標價。

### 5.4.1 三個操作

|操作|行為|disable 條件|
|---|---|---|
|決標|決標給最高出價廠商，該訂單轉入「已決標」|① 無人出價<br>② 最高出價有兩家以上相同|
|**指定成交廠商**|由內部從出價列表中手動選定一家廠商成交，該訂單轉入「已決標」|無人出價|
|進入加價拍賣|開啟「加價拍賣設定」彈窗（見 5.5）|無|

「決標」與「指定成交廠商」皆需二次確認，顯示成交廠商與金額，成功後觸發得標／未得標通知。

> **注記：「指定成交廠商」為本版新增流程**，用於處理同價、或內部判斷需成交給非最高價廠商的情形。以下細節待確認（見 8.5）：是否需填寫指定理由、是否限定只能在同價時使用、成交金額是否等於該廠商的出價金額。

## 5.5 「進入加價拍賣」彈窗

|欄位|必填|預設值|規則|
|---|---|---|---|
|拍賣開始日|是|今日|與 4.4 同規則|
|拍賣結束日|是|今日 + 7 日|與 4.4 同規則|
|廠商勾選|是（至少一家）|**全部勾選**|列出所有廠商。僅被勾選的廠商會收到加價拍賣通知並取得出價資格，未被勾選的廠商看不到此拍賣|

### 5.5.1 submit 後行為

|項目|內容|
|---|---|
|訂單流向|退回「拍賣進行中」tab|
|輪次|＋1|
|起標價|前一輪的最高出價金額；前一輪無人出價時為 0 元|
|出價限制|本輪出價必須高於起標價（起標價為 0 元時，出價 ≥ 0）|
|通知|對被勾選的廠商發出加價拍賣通知（模板待定）|
|前一輪資料|保留，不覆蓋。每輪各自留存起訖日、邀請名單、起標價、各家出價與時間|

### 5.5.2 加價輪可重複發起

輪數不限。每一輪結標後，都可在「已結標」的詳細彈窗中三選一：決標 / 指定成交廠商 / 再進入加價拍賣。

無人出價的拍賣同樣透過「進入加價拍賣」重新徵求出價，作為重新排定拍賣的方式。

## 5.6 已決標

|欄位|說明|
|---|---|
|orderNo|訂單編號|
|車輛資料|車牌、廠牌／車型、年份、里程、顏色|
|得標廠商|—|
|成交金額|—|
|決標輪次|第 N 輪|
|決標方式|決標 / 指定成交廠商|
|決標日期／操作人|稽核用|
|操作|「詳細」（唯讀，含各輪出價紀錄）、「完成」|

### 5.6.1 「完成」按鈕

付款與過戶為線下流程。線下完成後，由內部在此列表點「完成」（二次確認）標記該筆結案。系統不驗證款項與過戶狀態。

標記完成後：該筆訂單自「已決標」列表移除（或標記為已完成，見 8.6），且對外站的「已得標」列表不再顯示該筆。

## 5.7 狀態流轉

```
待排定拍賣 ──排定拍賣──▶ 投標中（第 1 輪）──截止──▶ 已結標
                                                     │
                          ┌──進入加價拍賣────────────┤
                          ▼                           ▼
                   投標中（第 N 輪）──截止──▶ 已結標 ──決標／指定成交廠商──▶ 已決標 ──完成──▶ 已完成
```

|狀態|所在位置|
|---|---|
|待排定拍賣|車輛管理|
|投標中|拍賣管理 → 拍賣進行中|
|已結標|拍賣管理 → 已結標|
|已決標|拍賣管理 → 已決標|
|已完成|見 8.6|

# 六、通知

通知管道：**Email + SMS**，同時於對外站登入後可看到站內通知。

**訊息模板文案待定，實作前需補齊。** 訊息不提供內部在送出前編輯。

|# |事件|收件對象|模板|
|---|---|---|---|
|1|第一輪拍賣已排定|全體廠商|待定|
|2|加價拍賣邀請|被勾選的廠商|待定（可帶入：車輛資訊、本輪起標價、本輪截止日、拍賣連結）|
|3|即將截止（催投）|該輪尚未出價的廠商|待定|
|4|得標|得標廠商|待定|
|5|未得標|該輪其他具出價資格的廠商|內容為未得標告知，不含金額與名次。例：「order:xxxx 抱歉您未得標」|

多語系：通知與介面均需支援多語系（語言清單見 8.7）。
