# 車輛拍賣平台 —— 功能規劃說明

**日期**：2026-08-03
**用途**：向非技術單位說明目前的功能規劃與拍賣機制
**狀態**：規劃中，部分事項待確認（見第 6 章）

---

## 1. 使用者角色

平台上有兩大類人：**公司內部人員**與**外部的二手車商**。

### 1.1 公司內部人員

不同職務看得到與能改的東西不一樣。完整拆分是這樣：

| 角色 | 主要工作 | 能看到底價嗎 |
|---|---|---|
| 車輛登錄員 | 車輛入庫、拍照、填寫車況 | 否 |
| 核價／估價主管 | 設定底價、核准售價 | **是** |
| 拍賣營運 | 排定拍賣、上下架、監控、撤標 | 待確認 |
| 財務 | 保證金、(發票 收款) | 否 |
| 交車／行政 | 過戶文件、交車安排 | 否 |
| 客服／爭議處理 | 車商申訴、退車 | 否 |
| 稽核 | 檢視所有紀錄（唯讀） | 是（唯讀） |
| 系統管理員 | 帳號與參數設定 | 否 |

**建議做法**：初期不必一次拆成八個角色，先做三個就好——**車輛登錄員 / 拍賣營運（含核價）/ 系統管理員**。

**例外**：「誰能看到底價」建議從第一天就做好控制，這件事後補的成本很高。

> **為什麼底價要保密**
> 如果車商在拍賣前就知道底價是 82 萬，成交價幾乎一定會停在「82 萬 + 一個加價單位」，我們就完全拿不到競價本來會帶來的溢價——而且從報表上很難看出來，因為每一筆看起來都是「有成交、有達到底價」。

### 1.2 外部使用者

| 角色 | 說明 |  |
|---|---|---|
| 二手車商（主帳號） | 車行老闆層級，管理員工帳號、設定每個採購員能出到多少錢、看全公司的紀錄 |  |
| 二手車商（採購員） | 實際看車與出價，受主帳號的額度限制 |  |
| 第三方檢驗員 | 如果採用外部檢驗，需要有帳號上傳報告 | **待確認** |
| 原借款人 | 是否讓借款人看到自己的車賣了多少 |  確認不用 |

初期可以先做「一家車商一個帳號」，等車商數量成長後再加子帳號與額度控管。

### 1.3 三項機密資料

有三樣東西**永遠不會出現在車商看得到的畫面上**：

1. **底價** —— 車商只看得到「已達底價」或「尚差多少」，看不到金額
2. **貸款未償餘額** —— 完全不對外
3. **車商自己設定的自動出價上限** —— 連公司內部人員在監控畫面也看不到，只看得到「這筆是自動出價」

撤標的理由也只有公司內部看得到，車商端只會顯示「已下架」（因為理由通常涉及借款人的個資）。

## 2. 車輛管理功能 - For 公司成員

### 2.1 車輛從回收到上架

完整的前置流程大致是：

```
違約判定 → 車輛回收 → 入庫 → 查驗拍照 → 決定要不要整備 → 定價 → 上架
```

**系統要涵蓋這條線的多長？** 三個選項：

| 選項 | 範圍 |  |
|---|---|---|
| **A. 只做「上架」（建議起點）** | 車輛資料手動輸入，前面全部維持線下作業 | 上線快、範圍單純，但看不到「入庫到上架」花了多久 |
| B. 涵蓋入庫到上架 | 加上入庫登記、查驗工單、整備紀錄 | 能看見並改善這段時間，但需要現場人員改變作業方式 |
| C. 涵蓋回收全流程 | 從違約判定、派車開始 | 全流程可視化，但要跟催收單位整合，範圍大很多 |

建議從 A 開始。

### 2.2 車庫（車輛清單）能做什麼


| 功能 | 說明 |
|---|---|
| 新增／編輯車輛 | 填寫規格、車況、上傳照片 |
| 車輛狀態 | 在庫 / 已排拍 / 拍賣中 / 已售出 / 已下架 |
| 篩選與搜尋 | 依廠牌、年份、訂單號、狀態 |
| 排序 | 最新入庫 / 年份 / 里程 |
| 排拍 | 直接把一台在庫車輛送進拍賣設定 |
| 下架封存 | 用「封存」而不是真的刪除，紀錄要留著 |
| 上架前預覽 | 存檔前先看一次「車商實際會看到的畫面」 |
| 上架前檢核清單 | 照片齊不齊、必填欄位、底價核准了沒、文件到齊沒 |



### 2.3 一台車要提供哪些資訊

車況資訊的完整程度**直接影響成交價**。車商如果無法確認車況，一定會把不確定性反映在出價上——也就是往低了出。

| 類別 | 內容                                                                                                         |
|---|--------------------------------------------------------------------------------------------------------------|
| 基本規格 | 車身號碼、車牌、廠牌、車型、年份、里程、排氣量、燃料、變速箱、驅動方式、顏色、座位數                         |
| 車況評級 | 車體 S / 5 / 4.5 / 4 / 3.5 / 3 / 2 / R（事故車），內裝另評 A–D，分數待定                                     |
| 車體傷痕圖 | 在車輛示意圖上標出每一處擦傷、凹陷、鏽蝕的位置                                                               |
| 照片 | 建議至少 20 張：外觀四角、正背面、左右側、引擎室、行李廂、儀表板（含里程）、前後座、四條輪胎、鑰匙、傷痕特寫 |
| 選配 | 引擎啟動影片、引擎聲音、底盤照片                                                                             |
| 文件 | 行照、保養紀錄、驗車紀錄、事故紀錄、未繳罰單                                                                 |

> **關於評級制度**：上面的評分方式（S / 5 / 4.5 …，內裝 A–D）沿用日本車拍（USS、TAA、JU）的既有標準，亞洲的二手車商普遍熟悉。好處是車商不用重新學，也方便跟市場行情對照；代價是內部人員需要訓練，評級跟實車不符時會變成爭議來源。

### 2.4 車況檢查要做到什麼程度

三個層級，成本與效果差很多：

| 做法 | 誰檢查 | 成本 | 對成交價的影響 | 爭議發生率 |
|---|---|---|---|---|
| A. 照片 + 自己勾選車況 | 內部人員 | 低 | 基準 | 較高 |
| **B. 標準化表單 + 評級（建議）** | 內部人員（需訓練） | 中 | 預估 +5～10% | 中 |
| C. 第三方檢驗報告 | 委外機構 | 高（每台檢驗費） | 預估 +10～20% | 低（責任可部分轉移）先不採用 |

檢驗費是固定成本，對高價車來說比例很低、對低價車比例很高。

**建議依車價分流**：超過一定價格門檻的車走第三方檢驗，其餘用標準化自檢。

## 3. 拍賣管理功能 - For 公司成員

### 3.1 建立一場拍賣要決定什麼

| 項目 | 說明 |
|---|---|
| 選一台車 | 從「在庫」車輛裡挑 |
| **拍賣方式** | 定時開標 / 即時同步拍 / 密封投標，逐台決定（見第 5 章） |
| 開始與結束時間 | 定時開標通常掛 3–7 天 |
| 起標價 | 從多少開始喊 |
| **底價** | 低於這個價不賣。**車商看不到** |
| 加價單位 | 依價格自動分級，或固定一個金額 |
| 立即成交價 | 選配，出到這個價立刻結標 |

### 3.2 底價怎麼訂 —— 這是最關鍵的待確認事項

有兩種完全不同的邏輯，算出來的數字可能差很大：

| 邏輯 | 算法 | 問題 |
|---|---|---|
| **保本邏輯** | 底價 = 貸款未償餘額 + 回收/保管/處分費用 | 帳面上不會產生損失，但如果車輛市價低於餘額（例如餘額 90 萬、市價 70 萬），底價根本達不到，車就會一直賣不掉 |
| **市場邏輯** | 底價 = 市場估值 × 折扣 | 車可以順利賣掉、處分時間短，但要認列帳面差額 |

**業界常見做法是兩者取較低者，並依差額大小分層核准：**

| 情境 | 誰可以決定 |
|---|---|
| 底價 ≥ 貸款餘額 + 費用 | 營運人員自己就可以設 |
| 底價 < 貸款餘額 | 需要主管核准 |
| 差額超過一定金額 | 需要更高層核准 |

> **一個建議納入制度的觀念**：訂底價時除了看「售價跟貸款餘額差多少」，也應該把「車繼續放著的成本」（保管費 + 折舊）拿來比較。如果只看前者，底價容易訂太高導致車滯銷，拖了半年之後的總結果，可能比一開始就便宜一點賣掉還差。

底價還有兩個配套建議：

- **底價設定畫面上直接顯示參考資訊**：貸款餘額、市場估值、同款車過去成交價、這台車已經累積的保管成本
- **底價的「修改」與「查看」都留下紀錄**——查看也要記錄，這是防止底價外洩相對關鍵的一項

### 3.3 拍賣進行中的監控

| 功能 | 用途 |
|---|---|
| 進行中拍賣看板 | 一眼看到每台車的目前價、出價筆數、距底價還差多少、剩多久 |
| 「上架 X 天沒人出價」提醒 | 及早調整策略 |
| 「快結標了還沒到底價」提醒 | 提前介入，例如打電話給已出價的車商 |
| 出價紀錄時間軸 | 誰在什麼時候出了多少（車商身分匿名顯示） |
| 異常出價提醒 | 例如金額明顯不合理 |
| 手動延長 / 提前結標 | 例外處理，需要權限與填理由 |
| 撤標 | 見下 |


## 4. 拍賣是怎麼進行的

以最主要的「定時開標」為例，一次完整的流程：

```
① 上架        設定拍賣方式、時間、起標價、底價
     ↓
② 開標        車商在列表上看到這台車，可以關注、可以出價
     ↓
③ 競價        3–7 天內隨時出價，看得到目前最高價（但看不到底價）
     ↓
④ 結標        時間到，最高價者得標 —— 但有三種可能結果
     ↓
⑤ 成交後      付款 → 過戶 → 交車 → 申訴期 → 結案
```

第 ⑤ 段目前還沒有具體規劃，多數問題列在第 6 章。以下說明 ③ 和 ④。

### 4.1 競價階段的四個機制

**（1）加價單位（級距）**

依目前價格分段設定最小加價幅度，避免有人一次只加 100 塊：

| 目前價格 | 最小加價 |
|---|---|
| 50 萬日圓以下 | 5,000 |
| 50 萬 – 200 萬 | 10,000 |
| 200 萬以上 | 50,000 |

單位太小競價會拖很久，太大車商會直接放棄加價。這組數字需要依實際車價水準調整。


**（3）匿名出價者**

出價紀錄上只顯示「出價者 A / B / C」，不顯示是哪一家車行。

這件事成本極低，但是**防止車商私下串通（圍標）最有效的手段之一**——車商互相看不到對方是誰，就很難確認「說好不加價的那家」有沒有遵守約定。

**（4）自動延長（軟結標）**

如果規則是「時間一到就結束」，最聰明的策略就是在最後一秒才出價，讓別人來不及反應。這會讓成交價低於它本來能到的水準。

**建議做法**：結標前 3 分鐘內只要有人出價，結標時間就往後延 3 分鐘。

這樣「最後一秒出價」就失去意義了，因為其他人永遠還有 3 分鐘可以回應。這是 Yahoo 拍賣與大多數車拍平台的通行做法。附帶效果是熱門車常常會延長 10–20 分鐘，價格在延長期間還會繼續往上跑。

代價是結標時間變得不可預測。

### 4.2 結標的三種結果

時間到的時候，系統看最高出價跟底價的關係：

| 情況 | 結果 |
|---|---|
| 完全沒人出價 | **流標**（無人出價） |
| 最高價 ≥ 底價 | **成交** |
| 最高價差底價在 10% 以內 | **進入議價** |
| 差超過 10% | **流標**（未達底價） |

### 4.3 議價 —— 讓流標的車還有機會

車輛拍賣的流標率通常在 20–40%。如果流標之後只能重新上架，車就要再等一輪，在庫時間會拉得很長。

**議價機制**（日本車拍稱為「商談」）：

1. 結標時最高出價 78 萬、底價 82 萬 → 進入「議價中」
2. 系統通知這位最高出價者：**你的出價沒到底價，願不願意加到 82 萬成交？給你 24 小時決定**
3. 同時核價主管可以在後台調整底價，或直接接受 78 萬
4. 如果他放棄，就依序問第二高、第三高的出價者
5. 全部都放棄 → 正式流標

好處是成交率會明顯提升、在庫時間縮短，而且公司對每一台車都保留最終決定權。

風險是如果車商摸清了規則，可能會傾向先出低價、等著被邀請議價。**配套建議**：只有在「差距小於 10%」時才啟動議價、議價金額由系統直接開出（就是底價），不開放來回喊價。

### 4.4 流標之後怎麼辦

| 路徑 | 什麼時候用 | 取捨 |
|---|---|---|
| **換一種拍賣方式重掛（建議優先）** | 第一次流標 | 可能吸引到不同的買家 |
| 調整底價重新上架 | 底價明顯訂太高 | 有效，但如果變成慣例，車商會學會「等下一輪比較便宜」 |
| 整備後重新上架 | 車況是主要問題 | 可能賣更好，但要先花錢 |
| 轉固定價格長期掛售 | 已經流標兩次 | 不再佔用拍賣資源，但去化較慢 |
| 整批出清 | 長期賣不掉 | 一次收回現金，價格較低 |

**建議優先考慮「換方式」而不是「降價」**，並且對降價重掛的次數設上限，避免形成觀望效應。

### 4.5 通知

通知看起來是小功能，但對成交價的影響其實不小。**「你的出價被超越了」是其中最關鍵的一則**——沒有這則通知，設定了自動出價的車商被超越之後通常就不會再回來了。

| 通知給車商 | 通知給公司內部 |
|---|---|
| 符合訂閱條件的新車上架 | 開標滿 2 天無人出價 |
| **出價被超越** | 快結標了還沒達底價 |
| 即將結標（結標前 1 小時 / 10 分鐘） | 結標結果（成交 / 流標） |
| 結標時間已延長 | 異常出價 |
| 得標 / 未得標 | |
| 議價邀請 | |
| 付款提醒 / 逾期提醒 | |
| 可以來牽車了 | |

**管道建議**：Email 加站內通知成本最低，但即時性有限。**建議盡早導入通訊軟體（LINE / WhatsApp）通知**——像「出價被超越」這種需要立刻反應的通知，用什麼管道送差別很大。

## 5. 三種拍賣種類

**建議把「拍賣方式」做成上架時的可選項目，由營運人員逐台判斷，而不是全站統一。**

### 5.1 三種方式的比較

| | 定時開標 | 即時同步拍 | 密封投標 |
|---|---|---|---|
| **怎麼跑** | 掛 3–7 天，期間隨時可出價 | 固定場次（例如每週三下午），大家同時上線，每台車 90 秒 | 期限內投一次密封報價，開標時最高價得標 |
| **看得到目前最高價** | 看得到 | 看得到 | **看不到**，只知道自己出了多少、共幾家投標 |
| **典型長度** | 3–7 天 | 90 秒 | 2–3 天 |
| **要準時到場嗎** | 不用 | **要** | 不用 |
| **自動出價** | 有 | 有 | 無（只能投一次） |
| **自動延長** | 前 3 分鐘 → 延 3 分鐘 | 前 15 秒 → 延 15 秒 | 無 |
| **立即成交價** | 無 | 無 | 可設 |
| **通常成交價** | 中 | **最高** | 偏低 |

### 5.2 各自的優缺點

**定時開標** —— 建議的主力方式

| 優點 | 缺點 |
|---|---|
| 車商不必準時到場，參與門檻最低 | 參與者太少時價格拉不高 |
| 車輛隨到隨上架，不必等湊場次 | 需要防最後一秒出價（用自動延長解決） |
| 有競價過程，價格會互相推高 | 週期較長（3–7 天） |
| 車商有時間好好評估車況 | 少了現場競價的節奏感 |

**特別適合我們的原因**：回收車是陸續進來的，不是成批到貨。定時開標不需要湊滿場次，查驗完就可以上架。

**即時同步拍** —— 日本大型車拍（USS、TAA、JU）的標準形式

| 優點 | 缺點 |
|---|---|
| **成交價通常最高**，現場氣氛會推高價格 | 車商必須準時到場，缺席就參與不到 |
| 不存在最後一秒出價的問題 | 需要湊滿場次，車輛要等 |
| 一場能處理大量車輛 | 車商只有 90 秒決策，可能傾向保守 |
| 貼近日本車商既有的習慣 | 系統建置與維運成本最高 |

**建議時機**：等車商數量成長、生態成熟之後再做——現在做，場次上沒有足夠人氣支撐。

**密封投標**

| 優點 | 缺點 |
|---|---|
| 車商互相看不到出價，**難以串通** | 成交價通常偏低，車商會保守出價 |
| 沒有最後一秒出價與跟價的問題 | 缺少競價熱度，參與感低 |
| 車商不用盯盤，操作成本最低 | 資訊不透明，需要車商信任平台 |
| 適合沒有公開行情、難估值的車 | 只有一個人投標時，價格可能很低 |
| **不會對外揭露公司的處分價格** | |

計價方式建議採「**付自己出的價**」（第一價格），規則直觀、車商容易接受。

### 5.3 什麼車用什麼方式

| 車輛狀況 | 建議方式 | 理由 |
|---|---|---|
| 常見車款、有明確市場行情 | **定時開標** | 車商敢出價，競價效果好 |
| 稀有車 / 高價車 / 事故車 / 難估值 | **密封投標** | 公開競價時車商容易互相觀望 |
| 一次上架多台同款車 | **密封投標** | 避免同款車互相排擠 |
| 定時開標流標過一次 | 改密封投標，或調整底價重掛 | 換機制可能吸引到不同買家 |
| 已經流標兩次 | 轉固定價格長期掛售 | 不再佔用拍賣資源 |
| 不希望對外揭露處分價格的車 | **密封投標** | 價格不公開 |
| 車商數量成長、生態成熟後 | 即時同步拍 | 屆時才有足夠人氣 |

代價是營運人員需要判斷力與訓練，規則也比較多。但好處是每台車都能用相對合適的方式賣，流標車也有明確的後續路徑。

## 6. 待確認事項

以下是需要業務、財務、風控單位提供答案的問題。**打星號的四項會直接影響 Phase 1 的機制設定，建議優先釐清。**

### 6.1 ★ 底價與帳務結算

這一區的答案會決定底價策略的合理範圍，進而影響整個拍賣機制。

假設一台車的結算是這樣：

```
成交價                    70 萬
－ 拖車費、保管費、整備費、過戶費
＝ 淨回收                 65 萬

貸款未償餘額              90 萬
－ 淨回收                 65 萬
＝ 差額                   25 萬  ← 這 25 萬怎麼處理？
```

- 底價目前是依「貸款餘額」還是「市場估值」決定？誰決定的？依據什麼？
- 有沒有可用的估值來源或工具（行情資料庫、鑑價服務）？
- 認列差額需要什麼層級核准？金額門檻是多少？
- **差額是否向原借款人追償？**
- 如果賣超過貸款餘額，超出的部分要退還借款人嗎？
- 拖車費、保管費、整備費可以向借款人請求嗎？
- 目前平均回收率（成交價 ÷ 貸款餘額）大約多少？
- 需要跟現有的貸後 / 催收 / 會計系統對接自動沖銷嗎？對接什麼？

> **為什麼這題影響很大**：如果差額可以向借款人追償，公司對較低成交價的接受度就高，可以偏向市場邏輯訂價、加快去化；如果不能追償，底價就得訂得保守，但也就更容易面臨長期流標。

### 6.2 ★ 車輛庫存與保管

- 回收後車輛停在哪裡？誰負責看管？
- **保管成本一天／一個月大約多少？**（訂底價時要拿來跟「差額」比較）
- 目前每月回收多少台車？平均車價區間？車型分布？
- 從違約判定到車輛回收，流程怎麼跑？誰執行？平均多久？
- 從入庫到可以上架，中間各段要多久？瓶頸在哪一段？
- 目前平均多久能賣掉一台車？
- 有沒有遇過賣不掉的車？放了多久？最後怎麼處理的？
- 是否需要先整備（清潔、小修）再賣？有沒有評估過效益？

### 6.3 拍賣中借款人清償 / 贖回

Phase 1 不做撤標功能，所以**必須在上架前就確認這台車可以處分**。這一區要確認的是「上架前該擋掉什麼」：

- **從車輛回收到可以處分，中間有沒有法定或內規的等待期？**
- **借款人的贖回權有多久？**
- 實務上多常發生「拍賣進行到一半借款人來清償」？目前怎麼處理？
- 如果真的發生，例外處理的流程是什麼？誰決定？
- 處分後有沒有義務向借款人說明售價？是要全程可查看，還是結案後給結算明細就好？

### 6.4 ★ 車況檢查要做到什麼程度

- 目前回收車有沒有做車況檢查？誰做？有沒有標準表單？
- 標準化表單與評級標準要由誰訂？誰負責訓練登錄人員？
- **（建議直接問車商）**決定要不要出價、出多少錢時，最看重哪些資訊？什麼情況下會傾向保守出價？會相信賣方自己填的車況嗎？

### 6.5 過戶與交車

- **過戶手續目前誰在跑？要多久？需要哪些文件？**
- 未來由誰跑？
  - (a) 公司代辦（可另外收費）—— 進度可掌握，但佔人力
  - (b) 車商自辦 —— 成本最低，但進度不可控，車可能長期還登記在公司名下
  - (c) 委託代辦業者 —— 折衷
- 過戶時點：收款後才過戶，還是過戶與交車同時？（建議收款後才過戶）
- 交車方式：車商自己來牽、公司送車（可收費）、還是委託物流？
- 車商買了之後遲遲不來牽車怎麼辦？收停車費？逾期幾天視為棄標？
- 交車時要點交什麼？（鑰匙幾把、行照、備胎、隨車工具、保養手冊）

### 6.6 稅務與發票

- **成交價是含稅還是未稅？稅率多少？**
- 二手車銷售在稅務上有沒有適用特殊的課稅方式？
- 發票 / 收據怎麼開？編號怎麼管理？
- 如果向買家收手續費，那筆手續費要另外課稅嗎？
- 首發市場是哪一國？（不同市場的稅制與過戶規定差很多，這題不確定的話，成交後的流程沒辦法定案）

### 6.7 付款條件與履約保障

- **目前賣車給車商的收款條件是什麼？有沒有票期、月結的慣例？**
- 付款期限訂多久？T+2 / T+3 / T+5 / T+7 工作天？
- 收款方式：電匯 / 支票 / 保證金抵扣 / 信用額度月結？
- 逾期怎麼辦？滯納金按日計？逾期幾天視為違約？
- 有沒有遇過得標後不付款的？多常發生？怎麼處理的？
- **要不要收保證金？** 選項：
  - 不收，純靠註冊審核把關
  - 年度會員保證金（一次繳固定金額）
  - 每台車保證金（出價前凍結一筆）
  - **信用額度制（建議）**：繳保證金取得數倍出價額度，例如保證金 50 萬 → 出價額度 500 萬
- 違約金比例訂多少？要不要向違約車商追償重新拍賣的價差？

### 6.8 車商生態

- 目前有往來的車商有幾家？前三家佔多少比例？
- **（問車商）**現在都從哪裡進車？用哪些平台？
- **（問車商）**習慣的拍賣形式是什麼？定時競標、現場拍、還是直接報價？
- **（問車商）**習慣的加價幅度大概是多少？
- **（問車商）**能接受繳保證金嗎？金額多少？年繳還是逐台繳？
- **（問車商）**用手機還是電腦操作？（車商多半在車行或外出時用手機，手機版體驗可能要列為基本要求）
- **（問車商）**平常用什麼方式聯絡？會看 email 嗎？
- **（問車商）**希望多久內付款？多久內能牽車？
- **（問車商）**一家車行大概幾個人需要帳號？
- 有沒有觀察到車商之間私下協調出價的情況？

### 6.9 爭議與退車

- 有沒有遇過車商買了之後說車況不對、要退車？怎麼處理的？
- 申訴期要訂多久？（建議交車後 7–14 天）
- 哪些事由可以申訴？（建議明列：里程不符、事故未揭露、泡水、引擎或變速箱重大故障、證件不符）
- 哪些不能申訴？（建議明列：一般消耗品、已揭露的瑕疵、外觀輕微傷痕、主觀不滿意）
- 舉證責任在誰？要不要求車商提出第三方鑑定報告？
- 處理方式：退車全額退款 / 減價補償 / 維修費分攤 / 駁回？

### 6.10 內控與稽核

- 車輛處分目前有什麼內控規範？
- 需要保留哪些紀錄？保存多久？
- 有沒有利害關係人交易的限制？（員工或關係人能不能買車）
- 稽核單位希望在系統裡看到什麼？

- 其他可能收入：車商年費 / 會員費、物流送車、車況鑑定、車商採購融資

## 7 決議不做的功能
**~~自動出價（代理出價）~~ 自動出價不做**

車商設定「我最多願意出到 85 萬」，系統**不會**直接跳到 85 萬，而是只出「打敗目前最高價所需要的最小金額」：

- 目前最高 70 萬、加價單位 1 萬 → 系統幫他出 71 萬
- 別人出 75 萬 → 系統自動跳到 76 萬
- 一路自動應戰到 85 萬為止，超過就停止並通知他已被超越

好處是車商設定一次就不用一直盯著螢幕，參與度會明顯提升，成交價也會更貼近車商真正願意付的金額。這是效益相當高的功能。

**車商設定的上限是機密**，公司內部人員在監控畫面也看不到。
